# Kodo TUI 设计方案

日期：2026-10-27。品牌：Codego AI 旗下独立产品 Kodo，Know · Organize · Do。

本文记录界面与命令设计。2026-10-28 已接入首版 T0–T2 的核心流程，实际支持范围与验收限制见第 13 节；下文包含后续设计，不能据命令表推定全部功能已上线。

## 1. 产品结论

Kodo 的第一版 TUI 是一个以主代理对话为中心、可以查看协作过程并沉淀可复用 Agent 的工作终端。

用户首先应能顺利完成工程任务，然后能回答三个问题：谁在做什么、结果有什么证据、这次方法能否下次复用。默认界面保持简单，复杂能力通过命令面板和详情页逐层展开。

推荐以 OpenCode 的导航与操作发现作为整体参考，以 Pi 的简洁输入和排队语义约束复杂度，吸收 Claude Code 的工具折叠与后台任务反馈、Codex 的变更与会话检查入口。这里的判断依据是公开文档和交互契约，不是同机性能、中文输入或视觉实测排名。

## 2. 同类产品比较

| 产品 | 本次公开资料确认的交互 | 借鉴点 | Kodo 的取舍 |
| --- | --- | --- | --- |
| OpenCode | `/` 命令、会话选择、外部编辑器、工具详情开关、`@` 文件引用、可配置 leader 快捷键、子会话导航 | 操作可发现，较多能力可以放在选择器和详情页 | 最适合参考整体操作组织；不把所有功能变成常驻面板 |
| Codex | 模型与权限选择、会话恢复、diff、上下文状态、Agent/聊天切换等入口；命令可随运行环境和版本变化 | 工程工作流、状态检查和会话管理 | 主画面突出修改、验证和待解决事项；不照搬依赖其服务器或云产品的命令 |
| Claude Code | 工具过程折叠、详细 transcript、后台 shell/agent 任务、任务清单、输入队列、子代理配置和独立上下文 | 长任务反馈、详细过程按需展开 | 计划清单与实际运行的子任务分开；主对话不被子代理原始日志淹没 |
| Pi | 对话、输入区和状态栏；Enter 引导当前任务、Alt+Enter 排队后续任务；工具输出折叠；tree/fork、扩展、技能和包；默认不内置子代理 | 核心简单、输入语义明确、扩展可组合 | 保持普通对话最短路径，同时提供 Kodo 原生协作与 Agent 资产闭环 |

注意：其他产品已经有 Agent、扩展或包生态，“能导入导出”本身不足以构成独占优势。Kodo 应把方法、工具/技能/MCP 依赖、使用条件、版本和验证案例连成用户可操作的复用流程。

本次抓取的 OpenCode TUI 页面包含 OpenCode 1→2 升级说明，因此不将其命令表与某个新内核提交视为完全同一版本。Claude Code 仅引用官方公开页面，不使用泄露源码。

## 3. 首发场景与范围

首发服务愿意配置模型的开发者和小型技术团队。TUI 与原 CodeGo 中转站分开，连接任意已支持的模型服务，不把 CodeGo 账号作为使用前提。

首发必须完成三个端到端流程：

1. 提出任务 → 查看工具执行 → 回答必要问题 → 查看修改与验证 → 得到交付。
2. 主代理自主分工 → 查看子任务状态 → 需要时查看证据或补充说明 → 主代理验收合并结果。
3. 使用一个 Agent → 查看依赖与验证情况 → 导出 → 在干净配置中导入并完成绑定 → 再使用。

第一版同时支持草稿保留和静态配置导出；较复杂的案例比较、版本采用等在同一命令体系中渐进增加。社区搜索、上传、评价和运营后台放在后续网页，不在第一版 TUI 内建设商城。

## 4. 信息架构

只区分三种核心对象：

- **会话**：用户的一段连续工作，包含主代理对话及相关任务。
- **任务**：一次实际执行，包括主任务、子任务和后台进程；后台进程与 Agent 用不同图标和类型名称。
- **Agent**：可复用的定义/能力包，有 ID、版本和依赖；运行中的某个 Agent 实例属于任务。

对应三个入口：会话选择器、任务面板、Agent 库。不要把 Agent 库和正在工作的子代理混在一个列表中。

### 4.1 默认界面

默认单列对话，输入区固定在底部。宽终端可打开右侧任务面板，初始不强制展开。示意为展示用状态，不是当前任务的真实数据：

```text
 Kodo   agent-harness                         模型：DeepSeek   本地工作区
──────────────────────────────────────────────────────────────────────
 你  修复超时行为，并补充回归测试。

 Kodo  我会检查实现与现有测试，再验证修改。

 ▸ 探索现有测试    子任务 #2    已返回，待验收
 ▸ 修改超时逻辑    主任务       进行中
 ▸ 更新回归测试    子任务 #3    进行中

 ✓ 读取 3 个文件                         [展开]
 ▸ 检查回归测试                          运行中 12s

 当前：等待回归结果 · 子任务 1 运行 / 1 待验收
──────────────────────────────────────────────────────────────────────
 发给主代理 > 补充：保持现有取消语义不变。
 Enter 发送   / 命令   @ 引用   Ctrl+O 过程详情
 上下文 38%（估算） · 输入 24k / 输出 3k · 费用未配置
```

宽度规则：

- ≥120 列：允许对话 + 约 34 列任务面板；主对话剩余空间不足时自动折叠。
- 80–119 列：单列；面板作为全屏临时页，关闭后返回原滚动位置与输入草稿。
- <80 列：紧凑布局，隐藏次要计量，只保留状态和命令入口。
- 小于约 60×16 时显示可用但受限的紧凑视图，不持续重绘大框线。

标题只放项目、模型与必要执行状态；品牌口号放空状态/帮助页。状态不能只靠颜色区分，使用“运行中、待回答、待核实”等文字。

### 4.2 工具与交付卡片

成功的读取/检索可合并为一行；失败、用户提问、待核实操作和验证结果保持可见。流式输出默认跟随底部，用户向上滚动后停止自动跳动，显示“新内容 N 条”。

工具详情包含参数摘要、退出码、耗时、分页输出及原始证据引用。长输出不反复整段刷屏。只展示模型提供的工作说明、工具事实和结果，不要求展示内部推理。

最终交付卡片至少区分：

- 运行结束状态；
- 交付物/修改文件；
- 验证命令、结果与覆盖范围；
- 未验证或待处理事项；
- 可保留的 Agent 草稿（存在时）。

“进程退出 0”“子代理 completed”“模型声称完成”“宿主验收通过”不能合并成一个绿色成功标志。

## 5. 协作交互

任务面板按主任务与其子任务展示浅层结构；不默认绘制聊天拓扑图。

每项显示：短名称、Agent ID/版本、目标摘要、状态、最近活动、耗时、待回答数量、验证状态。模型/工具/MCP 和写范围放详情页。只有存在记录时才展示委派理由，不让界面编造解释。

选择子任务默认只查看详情。主输入区始终标明“发给主代理”；不会因浏览子代理而偷偷切换消息收件人。向子代理发送消息必须使用任务详情的明确动作或 `/tasks message`，显示发送对象，并保留主代理可审计的记录。

用户不需要手动创建 Agent 才能开始工作。`explore` 是执行能力/任务用途，不做必选职业类型。主代理可使用临时配置；保存后才成为库中的可复用资产。

子代理的问题先通过既有通信机制流向同伴或主代理。只有主代理需要用户决策时，TUI 展示待回答卡片。多个问题不抢占输入焦点，选定问题后才将输入绑定到该问题。

计划清单显示“准备做什么”；任务面板显示“实际正在运行什么”。两者不互相冒充。

## 6. 输入、状态与快捷键

### 6.1 输入语义

| 输入方式 | 行为 |
| --- | --- |
| 普通文本 + Enter | 空闲时启动任务；运行中作为补充，在内核允许的边界送达 |
| `/next 文本` | 排队为后续任务；显示可查看、修改、撤回的队列 |
| `/decision 文本` | 明确改变约束，调用现有 decision 路径；显示旧计划可能需复核 |
| 回答卡片 | 绑定 question ID 后提交，不默认把任意新消息当作某个问题的答案 |
| `@文件路径` | 文件搜索与引用；默认附路径，由工具按权限读取，不默默塞入整文件 |
| `@agent:author/name@version` | 明确指定希望使用的 Agent，显示可解析的选择标签；主代理仍负责整体交付 |
| `/paste` … `/send` | 保留现有多行输入兼容方式；粘贴内容不当成斜杠命令执行 |

Agent 标签在未具备完整绑定/路由支持时不推出，只使用 `/agents run`。不要让看起来成功的标签被悄悄忽略。

### 6.2 快捷键

| 按键 | 行为 |
| --- | --- |
| Enter | 发送、选择或确认当前明确操作 |
| Shift+Enter | 支持的终端中换行；不支持时提供外部编辑器及 `/paste` |
| Tab | 接受补全或选择面板下一项 |
| Shift+Tab | 打开权限选择，保留当前输入草稿 |
| Ctrl+P | 命令面板；也可直接输入 `/` |
| Ctrl+O | 展开/收起工具过程；不改变模型上下文 |
| Ctrl+G | 外部编辑器，按平台安全传参，不插值拼 shell 命令 |
| Esc | 优先关闭补全/面板；主对话、空输入且有活动任务时请求中断当前轮次 |
| Ctrl+C | 首次请求中断并保留草稿；1.5 秒内再次按下会等待必要清理后退出 |
| PageUp / PageDown | 浏览历史，停止自动跟随 |

终端原生复制粘贴优先保留。所有关键操作都有命令/按钮替代，避免依赖 Windows Terminal、tmux 或 SSH 会截获的组合键。`/help keys` 显示当前实际绑定与可用回退。

### 6.3 停止与退出

- `/stop` 默认中断当前主轮次，保留记录；仍显示子任务/后台进程是否继续，不暗示全会话停止。
- `/stop all` 请求停止整个会话的执行，等待内核核实收敛。只有相应接口可保证范围时开放。
- `/cancel` 保留为已有终止语义的兼容命令，不偷偷改成可恢复中断。
- `/quit` 在空闲时退出；活动任务存在时，显示“中断并退出 / 返回任务”，选择中断后等待保存与清理。
- 初版不承诺关掉本地 TUI 后任务还能继续。远端或 daemon 执行属于后续能力。
- `/resume` 首先打开会话和恢复状态；取消终态需要后续 run 时明确显示“继续为新任务”，不能伪装成恢复原终态。

## 7. 命令设计

### 7.1 十二个主入口

命令默认打开选择器或面板，参数形式供熟练用户使用。首发菜单最多展示这十二个入口，其他操作放子命令和上下文动作。

| 命令 | 主要用途 | 实现基础与边界 |
| --- | --- | --- |
| `/help` | 命令、快捷键、使用方法 | 新增界面；依据真实注册表生成 |
| `/new` | 新会话 | 复用创建入口；第一版活动主任务未停止时不启动第二个主任务 |
| `/resume` | 历史会话选择、恢复/后续工作 | 已有 sessions/runs、recover、continue；按实际状态选择动作 |
| `/model` | 查看/选择模型 | 已有模型绑定；首版在新会话生效，禁止悄悄更换正在执行的模型 |
| `/agents` | Agent 库、导入导出、保留草稿 | 包、作者工具、草稿和案例接口；TUI 待接入 |
| `/tasks` | 当前主/子任务与后台进程 | 已有 snapshot、events、calls、消息和子代理控制接口 |
| `/changes` | 文件变化、交付物及证据 | 已有写入记录/快照；Git diff 作为可选补充，标明基线 |
| `/check` | 运行和查看项目验证 | 使用已配置、允许执行的 verify.run/验证适配；未配置时引导配置 |
| `/context` | 当前上下文、来源、压缩和用量 | 已有 context/context-report/knowledge；按实际投影显示 |
| `/settings` | 连接、执行权限、绑定、界面设置 | 复用宿主配置；不在模型对话中输入密钥 |
| `/stop` | 中断当前轮次或停止会话 | 复用 interrupt/cancel，严格区分范围 |
| `/quit` | 保存并退出 | 复用 shutdown；执行中按上节处理 |

保留已有 `/status`、`/decision`、`/next`、`/cancel`、`/paste`、`/send`；它们能搜索到，但不增加初始菜单负担。`/status` 打开会话概览，不再输出一整屏 JSON。

`/new` 不等于清理工作区；`/resume` 不等于重放所有工具；`/stop` 不等于回滚文件。

### 7.2 Agent 命令

| 命令 | 行为 | 发布阶段 |
| --- | --- | --- |
| `/agents`、`/agents list` | 搜索本地 Agent：用途、作者/版本、准备状态、案例记录 | 首发 |
| `/agents show <id@version>` | 方法摘要、模型要求、工具、技能、MCP、依赖、验证范围 | 首发 |
| `/agents run <id@version> "任务"` | 显式创建受管子任务；无活动主任务时先进入主代理任务流程 | 首发 |
| `/agents import <file.zip>` | 检查归档并导入；展示依赖和待绑定项，不等于已激活 | 首发 |
| `/agents export <id@version> <file.zip>` | 导出声明中可分发的内容 | 首发 |
| `/agents save <task-id>` | 向导选择“保存配置”或“提炼方法”，后者明确调用模型 | 首发 |
| `/agents drafts` | 查看、编辑、接受或放弃沉淀草稿，绑定具体 digest | 首发 |
| `/agents new "用途"` | 通过对话创建草稿，选择能力与案例 | 第二批，可先提供现有作者 CLI 入口 |
| `/agents test <id@version>` | 运行选定冻结案例，显示模型调用和预算 | 第二批 |
| `/agents compare <baseline> <candidate>` | 展示相同条件下的案例差异，不只看一个成功样例 | 第二批 |
| `/agents adopt <id@version>` | 基于匹配证据采用版本 | 第二批 |
| `/agents rollback <id>` | 查看历史版本与依据，再按现有采用/回退策略操作 | 第二批 |

`/agents run` 的 scope、slot 等复杂参数主要通过选择器填写，并提供高级参数输入，不要求新用户手写 JSON。缺少依赖时先展示缺项，不静默换 Agent。

当前 CLI 的 `agent` 与 `package` 分属作者和分发接口。TUI 对用户统一称“Agent”，底层继续复用 PackageRegistry 和作者接口，避免建立第二套包格式。

一个 Agent 的状态至少区分“已导入、待绑定、可运行、有案例证据、已采用”。这些状态不是简单线性升级：有证据的包也可能在本机缺绑定。版本、绑定状态、采用状态和案例证据分别存储/显示。

### 7.3 任务、变更与上下文子命令

| 命令 | 行为 |
| --- | --- |
| `/tasks show <id>` | 任务说明、Agent 版本、能力、执行与验收证据 |
| `/tasks logs <id>` | 分页工具记录，订阅新增事件 |
| `/tasks message <id> "内容"` | 明确发给指定受管子代理，调用 submitAgentInput |
| `/tasks interrupt <id>` | 中断子代理当前轮次，显示收敛中状态 |
| `/tasks cancel <id>` | 终止指定子任务，说明其已有文件修改保留 |
| `/tasks answer <question-id>` | 选择待回答问题，不依赖容易复制错误的长 ID |
| `/tasks resolve <call-id>` | 打开影响核实面板；展示原始证据，沿用宿主核实规则 |
| `/changes diff [path]` | 查看本任务可归属的变化；Git 工作树整体 diff 单独标注 |
| `/changes rewind` | 预览可恢复检查点与限制；范围和阻塞检查通过后执行 |
| `/check run [name]` | 运行宿主已声明的验证命令，不接受任意 shell 字符串冒充验证配置 |
| `/check results` | 验证历史、覆盖范围与对应文件版本；文件再变后显示“结果已过期” |
| `/context sources` | 查看知识/归档来源，按需读回 |
| `/context usage` | 主代理/子代理/摘要用量与未知部分 |
| `/context compact` | 后续高级操作；有内核手动入口和预算契约后才开放，首发只展示自动压缩状态 |

后台进程在任务面板中可选，但只能使用其真实支持的读取/停止操作。不得将代理消息或 interrupt 动作机械套用到进程句柄。

对尚无对应服务接口的动作，在开发版标为待接入；发布版不显示可点击的空实现。以上子命令不是当前 CLI 已支持的命令声明。

### 7.4 设置与运行策略

`/settings` 包含模型连接、权限/沙箱、Agent 绑定、验证命令、预算和显示设置。首次只展示连接和当前执行能力；高级项折叠。

设置改变必须说明生效范围：立即生效、下一次请求、下一任务或下一会话。若内核要求冻结配置，就创建新会话或在安全边界切换，不仅改 UI 标签。

命令面板分为“本地查看”“执行操作”“模型请求”三类，必要时显示费用提示。打开页面、搜索本地 Agent、查看调用不应发起模型请求。

## 8. Agent 导入导出与持续改进

导出包可以包含：卡片方法、能力声明、允许分发的技能文件、MCP 配置模板/版本约束、依赖清单、使用说明和冻结案例。它不保证外部服务、系统程序和模型在接收者机器上已可用。

凭据、个人模型端点中的秘密、运行历史、项目私有文件和本机绝对路径不默认传播。MCP 一般导出连接/启动声明与所需绑定，而非直接导出个人令牌或所有服务端二进制。包内容以现有显式分发清单为准。

导入流程：

```text
选择归档 → 检查身份/版本/内容 → 导入本地库
         → 列出待绑定模型/工具/技能/MCP
         → 用户配置与宿主授权 → 准备依赖/验证 → 用于任务
```

运行后沉淀流程：

```text
已完成任务 → 查看候选配置/方法 → 保存草稿
           → 补充适用范围与案例 → 与已有版本对照 → 接受新版本
```

保存配置不自动调用模型；提炼方法会调用模型，两者在界面明确区分。一次成功只能标明该次证据，不产生“可靠度 98%”之类无依据评分。改进产生新版本，已有运行继续引用原版本。

社区第一步可以是网页浏览和下载包，TUI 负责本地导入与使用。待远端协议、账户和内容管理就绪，再增加 `/agents search --remote` 与发布入口；本版不承诺上线社区，也不执行上传。

## 9. 技术方案

### 9.1 默认选型

推荐先用 Ink + React + TypeScript，沿用 Node 运行环境。现有 readline 作为非 TTY 和兼容降级路径；`kodo run --json` 继续服务脚本。

OpenCode 的交互值得参考，但不因参考它就必须切换渲染库或整个运行时。用一个小原型验证 Windows Terminal 中文输入、长输出、滚动和终端恢复；原型达不到门槛再比较 OpenTUI/Pi TUI，避免在初期自研终端框架。

入口规划：交互 TTY 中裸 `kodo` 打开首页，`kodo chat` 打开对话；非 TTY 的裸命令保持帮助/明确提示，不偷偷进入交互状态。现有命令行参数保留。

### 9.2 一套内核、一个写入者

```text
终端输入/选择器
       ↓
TUI 命令与界面动作
       ↓
Application / 现有 Agent、包、案例服务
       ↓
持久事件 + 分页快照
       ↓
TUI 视图状态 → 终端渲染
```

一个数据目录只有一个负责运行的 Application。TUI 不为 `/agents` 等动作再启动会打开同一 Store 的 CLI 子进程；将现有 CLI 内嵌的业务编排提取成可复用函数后调用，保留原 CLI 外壳。

不让 UI 持有调度、预算结算或权限判定。视图状态只保存焦点、展开项、滚动位置、输入草稿和事件游标。API 缺口只补对应查询/动作，不为 TUI 重新设计整个内核。

使用现有事件序号作为游标：订阅、读取快照和补齐事件之间采用可去重的顺序；重开时从持久状态重建，不重放写操作。模型文本流可短暂缓冲，最终文本以持久结果为准。

TUI 不能通过“界面恢复了”声称后台进程已经恢复；进程与模型流是否可续接取决于内核。远端模式可后续使用现有 Web/SSE 服务，但首发无需常驻 daemon。

### 9.3 渲染与资源

- 文本流合并刷新，例如每 33–50 ms 一次；完成、错误、问题等关键事件立即更新。
- 长日志分页/可视区域渲染，不把全部工具输出复制进每个 React 节点。
- 未聚焦的子任务只更新摘要与计数；打开详情后再加载原文。
- 使用现有终端输出净化能力，文件/工具输出保持为数据。
- 终端异常退出时恢复光标、raw mode、备用屏幕和粘贴模式。
- 不依赖 emoji 宽度、颜色或鼠标才能完成操作；支持无颜色输出。

## 10. 实施顺序

### T0：终端原型与命令骨架

完成中文多行输入、滚动、流式文本、选择器、终端缩放与退出恢复。接真实 Application 的普通任务，命令只先接 help/new/resume/model/settings/quit。保留原 readline。

通过条件：Windows Terminal + PowerShell 的中文输入和多行粘贴不误提交；窄屏不破版；长输出不吞键；单次点击/按键只触发一次动作。

### T1：工程任务与协作闭环

接 tasks/changes/check/context/stop；展示子任务、问答、后台进程、核实状态和最终验证。保留 next/decision 的已有语义。

通过条件：真实任务可从输入到交付；中断/取消不会被 UI 显示成已经验证成功；重复打开页面不新增模型请求；检查结果能关联所验证的文件状态。

### T2：Agent 复用闭环（首个公开 Alpha 必须包含）

接 Agent 搜索、详情、显式运行、导入、导出、保存配置和草稿确认。复杂作者与案例比较先提供现有 CLI 兼容入口或后续接入。

通过条件：A 环境导出、B 干净环境导入，准确显示缺失绑定，完成绑定后使用同一版本完成示例任务。用户能解释导出了什么，以及没有导出什么。

### T3：进化与社区连接

补充方法提炼、新建 Agent、案例比较/采用/回退、远端社区检索及发布。上线顺序仍为产品可用 → 可复用案例积累 → 社区扩展。

## 11. 验收任务

| 场景 | 验收内容 |
| --- | --- |
| 小型单代理修复 | 输入、工具输出、diff、验证、最终回复完整；UI 操作不额外产生模型调用 |
| 两个独立子任务 | 能看到分工与证据；切换详情不改变输入接收者；主代理验收后交付 |
| 长输出与错误 | 大日志可读、可滚动；错误不被成功摘要隐藏；输入草稿保留 |
| 中断与取消 | 操作对象/范围清楚，收敛中状态可见；退出等待必要清理 |
| 待回答问题 | 多个问题有明确身份；回答不会误发给其他任务 |
| 会话重开 | 从持久状态恢复显示，不重复工具写入；不承诺恢复已经不存在的进程 |
| Agent 可移植性 | 包依赖可检查，缺少绑定可诊断，导入后可以运行；版本与证据一致 |
| Windows 输入 | 微软拼音、中文/英文混排、宽字符、多行粘贴、Shift+Enter 不支持时的回退 |

性能原型固定一组本地记录（例如一万条事件、含大工具输出）测输入到显示延迟、滚动、内存和事件补齐；暂定本地输入显示 p95 <100 ms，测得后记录环境。该指标不包含网络模型响应时间。

不要用截图漂亮或组件单测通过替代真实终端验收。TUI 不需要第一版完成全部内核优化，但它所展示的终态、取消、验证和未知影响必须真实。

## 13. 当前实现范围（2026-10-28）

入口为 TTY 中裸 `kodo` 或 `kodo chat [任务]`。`chat --plain` 与非 TTY 保留行输入，`run --json` 保留脚本输出。渲染使用 Ink 8 / React 19，业务调用共用 CLI 创建的 Application；页面浏览不会另开 Store 或发起模型请求。

空首页居中显示 Kodo 点阵标识；顶部仅保留名称／版本和工作区，底部为完整圆角边框的多行输入框与一行权限模式／模型／状态。界面自有文案使用英文，用户内容与模型回复保留原文。标识由 `brand/kodo-mark.svg` 同源导出为 32×14 和 16×7 两种点阵尺寸，保留曲线留白；矮屏不足时隐藏标识以保住输入。网站与应用的矢量源文件、透明 PNG、ICO、ICNS 及导出说明见 `brand/README.md`。

已接入十二个主入口及 `status/decision/next/cancel/paste/send` 兼容命令。支持中文宽字符编辑、字面粘贴、路径补全、外部编辑器、历史滚动、流式合并刷新、临时面板和宽终端任务侧栏。键入 `/` 和 `@` 即时显示命令／文件候选，↑↓ 选择、Enter／Tab 接受、Esc 关闭；粘贴内容不触发候选，加载中的文件候选不会因 Enter 误发任务。文件查询只读文件名，不改变面板或运行，输入变化后忽略旧查询。`Ctrl+P` 或 `/help` 打开完整选择器。首次 Ctrl+C 中断，1.5 秒内第二次通过正常清理退出，原始按键和 SIGINT 共用同一手势状态。按 Shift+Tab 或 `/permissions` 打开 Ask／YOLO 权限选择，批准策略立即作用于后续工具调用，重启恢复 Ask；工具授予、沙箱与连接继续由宿主配置，模型选择仅在新会话生效。

Ask 对文件修改、通用命令、网络工具与 MCP 调用逐次显示工具名、所属任务、工作区及参数；默认选中 Deny，Allow once 只批准当前调用，Esc 拒绝。YOLO 自动批准等待中及后续已经获工具授权的调用。专用批准回调位于校验后、取得文件锁及副作用开始前，异常、取消、过期和非 true 响应均拒绝；等待后重新核对权限和范围。等待沿用工具期限，过期不自动执行。普通读取、私有产物、宿主声明的只读命令以及已启动进程的输出读取免于重复询问。TUI 会话保存需要交互审批的标记，非 TUI 执行入口要求回到 `/resume`；模式本身不持久化。此交互参考 [OpenAI 官方权限文档](https://developers.openai.com/codex/permission-modes)，Kodo 的 Ask 是逐次工具审批，不实现 Codex 的自动审核服务。

任务页支持主／子任务证据、显式定向消息、问题选择与回答、中断／终止、后台进程输出和所属任务的全部后台进程停止。历史会话先恢复显示，执行前重新核对原宿主配置。变化页基于本任务保留的原生检查点，不把整个 Git 工作树变化归属给任务；恢复文件需先预览。宿主验收与运行结束分别显示。

`/check` 只执行宿主已批准的 `verify.run` 或 `--verify-command`。验证证据保存运行版本与同会话已记录文件路径的内容摘要；重新查看结果会检查这些路径是否改变。未记录的依赖、目录内容和超限文件不在完整性承诺内，界面明确显示覆盖不足。`/context` 展示自动压缩、来源与用量，手动压缩未开放。

Agent 库支持本地搜索、版本与依赖详情、输入／范围向导、显式受管任务、ZIP 导入导出、从本机 JSON 文件绑定、依赖准备、静态配置保存、按摘要编辑和确认保留草稿。已导入包按原分发清单导出；裸卡片若重新序列化改变内容摘要，必须明确指定新版本。

本地 T3 已接入：`/agents new` 预览创建用途、身份、工具和输出目录，确认后调用现有作者服务；`--template` 明确选择离线模板。`/agents method 任务ID --description "适用任务" ...` 从本会话已完成任务的有界证据提炼方法，`/agents save` 提供对应选择。模型作者使用同一 Application 的独立有计量运行，冻结 `toolChoice=none`，不提供原生或协作工具；模型错误、无效方法或中断不会写入草稿。输出包含 AGENT.md、分发声明与 ZIP，保持未导入、未采用。Skill/MCP 资源不静默丢弃，当前方法提炼需显式选择可分发内置工具。

`/agents test id@version "case.json"` 冻结案例并预览执行条件，确认后在独立空目录创建冻结输入，驱动模型前记录真实执行 ID；保留失败和中断证据。`cases [id@version]` 分页浏览、`cases show 执行ID` 查看证据，`compare 基线ID 候选ID` 检查同条件结果，`adopt id@version --runs ID,...` 与 `rollback id --runs ID,...` 重新核对包、案例、条件和采用指针后更新本地版本选择。固定宿主 `--verify-command` 对应案例命令 `default`，程序必须是绝对路径。作者和案例都接受停止、取消与退出，复用原 Application，不另开 Store。

相同包和配置可重复激活原工具、Skill 与 HTTP MCP，仍重新核验包与示例；stdio MCP 仍固定原工作区，同一 Application 中的同名扩展不能跨版本覆盖。遇到这些合同冲突明确说明，需按相应工作区／版本分别启动；只用内置工具的方法可在一个 TUI 中完成跨版本案例比较、采用与回退。T3 的远端社区、上传和发布按当前范围排除。

验收包括新增 TUI 集成测试、Windows ConPTY 中的中文文本输入／本地模型与真实文件工具循环／退出恢复，以及 Agent 跨环境导出、缺绑定诊断、绑定后运行同版本。本轮额外实测了作者模型请求、ZIP 导入、冻结案例断言和有证据采用。ConPTY 注入文本不能替代微软拼音实际组合输入验收；Linux/macOS 终端、各终端 Shift+Enter 和真实收费模型尚未在本轮实机认证。

一万条记录（包含 12 万字符工具输出）在滚动和流式刷新同时进行时，真实 ConPTY 80×24 的输入注入至输出写完 p95 为 55.973 ms；48／80／120 列内存 TTY 分别为 57.525／55.887／59.541 ms。连续冷浏览 100 页的投影 p95 为 0.909 ms、最大 12.487 ms。环境为 Windows 26200、Node 24.13.0、i7-14700K；运行 `node scripts/benchmark-tui.mjs --terminal --scroll --stream --output report.json` 可保留逐次原始数据。这不包含物理键盘、微软拼音组合或屏幕绘制延迟；离线直接跳穿全部历史首次约 1.5 秒，界面没有该跳转动作。

验证命令为 `npm run check`、`npm run build` 和 `npx --no-install vitest run`；TUI 定向入口为 `npx --no-install vitest run tests/tui`。ConPTY 实测已确认浏览不增加模型调用、字面多行粘贴、固定宿主验证、外部改动标记过期、停止长作者请求与退出后 raw mode 恢复。恢复回归同时验证未知写入阻止完成、明确核实后创建后续任务、独立工作保留，以及原终态和已发生写入不重放。

前期 T3 完整回归覆盖 141 个文件、1547 项测试，原始结果为 `140 passed / 1 failed` 文件、`1538 passed / 1 failed / 8 skipped` 测试；唯一失败是长读取组单独设置的 20 秒外层超时。8 项跳过均为 Windows 上不适用的 POSIX 沙箱与 FIFO 场景。

移除长读取组的单独时限、沿用统一的 30 秒集成测试时限后，补测结果为 `1 passed` 文件、`10 passed` 测试，功能断言和内核时限保持不变。完整回归与补测的原始记录分别保留在 `.kodo/tui-refinement-complete.{log,json}` 与 `.kodo/tui-refinement-progress-final.{log,json}`。

本次输入框与权限模式回归为 `20 passed` 文件、`253 passed` 测试，覆盖 TUI、工具批准、真实文件和进程、原有工具执行、后台任务、运行循环以及 CLI 宿主恢复合同；原始记录保存在 `.kodo/tui-permissions-regression.{log,json}`。`npm run check` 与 `npm run build` 均通过，构建清单与当前源码及产物摘要一致。Windows ConPTY 使用明确标注的本地脚本模型实测：批准前文件不存在，Shift+Tab 打开权限选择，Allow once 后才实际写入，切换 YOLO 后底部模式更新，双按 Ctrl+C 以退出码 0 恢复终端。前一轮即时补全与界面简化的 `11 passed` 文件、`155 passed` 测试记录仍在 `.kodo/tui-quiet-regression.{log,json}`。

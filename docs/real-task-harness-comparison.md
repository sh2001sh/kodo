## 如何读这些指标

- **原生完成**：harness 退出且提交了非空最终答复。这只能证明交付结束。
- **严格验收成功**：全部任务要求、独立功能检查、相关测试、类型与静态检查、修改范围、最终答复均满足，且未读取副本外的解题源码或评测程序。报告任务还须通过源码事实复核。
- **质量分**：按固定权重衡量要求覆盖程度；不等于完整的事实准确率、代码可维护性评分或安全证明。
- **交付耗时**：从运行开始到最终交付，包括模型思考、工具执行和代理自行运行的测试。外部独立验收时间不计入。
- **每次成功摊销耗时/费用**：全部尝试的总时间/估算费用除以严格验收成功数，保留失败尝试的投入。
- **用量**：逐请求读取上游 HTTP 返回的 input/output/cache 字段，不采用 CLI 面板的费用值。输入中已经包含缓存命中部分，输出中已经包含推理部分，不重复相加。

每个 harness 每种任务只有两次。任务之间难度、运行测试数量和输出长度差异较大；总体均值是三类任务等权的本次观测，不构成跨仓库排名或统计显著性结论。

## 任务与独立验收

### 1. 源码上手报告

只写 `REPORT.md`。说明当前内核、能力包分发、依赖准备、MCP、操作系统沙箱和写入恢复，区分默认与授权、已实现与计划、平台验证范围；至少三个限制、三条支持的命令、六个真实引用，其中三个是源码。

评分：六类源码事实各 10 分，共 60；有效引用 20；支持的命令 10；修改范围 10。严格成功还要求原生完成且最终答复非空。全文人工对照冻结源码复核，材料性矛盾使对应事实类别失败。额外发现但不在六类权重中的错误单列，分数不是穷尽的事实准确率。

### 2. 历史原文游标回归修复

在真实 `src/runtime/history.ts` 受控注入 `position = end` 变成 `position = 0` 的回归；代理只知道继续请求重复开头的用户症状。只允许改该文件。独立检查 Unicode 原文无损重建与游标严格前进、非法分页边界拒绝、跨会话引用拒绝；另跑冻结的 context/context-hardening 测试、TypeScript、ESLint。

这是在真实模块中的受控故障，不代表未经修改的主仓库仍有该缺陷。独立验收前已验证负控失败、正确实现正控通过。

### 3. 包管理版本查询功能

新增 `PackageRegistry.versions(id)` 和 `kodo package versions author/name`：每项仅 `{version,digest}`，按三段数值版本降序；合法缺失 ID 返回 `[]`，非法 ID 和被篡改的目标版本明确失败，不混入其他包，不改采用指针，不执行包代码，不建运行时数据库，无需模型凭据；更新文档和新增正常/失败路径测试。

独立 11 项检查覆盖空注册表、数值排序及精确字段、其他/缺失包、非法 ID、采用指针、CLI 无凭据、CLI 缺失与非法 ID、惰性与指针、篡改拒绝、文档；另跑冻结的既有包管理测试和提交的新测试、TypeScript、ESLint。负控与参考实现正控在模型运行前完成。

两类代码任务评分一致：独立功能 60、相关测试 10、类型与静态检查 10、范围 10、完成答复 10。独立验收在另一个副本重建，只移植允许的实现、文档和新增测试，保留冻结的依赖、配置及既有测试，防止修改验收配置获得假通过。

## 原始评分与复核

本轮自动验收程序有缺陷。`results.json` 与每轮原始日志保持不变；`audited-results.json` 从同一份产物派生修正，未重跑模型。报告语义复核是在首份报告出现后确定的**事后复核**，不得称为预注册评分。

1. 测试摘要匹配没有剥离 ANSI 颜色码，导致 exit 0 且实际通过的 Vitest 结果被判失败。所有代码轮次统一从原日志剥离颜色码，仍要求退出码 0、存在通过摘要和要求的新测试。
2. 报告匹配只认少数 `npm` 命令，漏掉任务提供的真实 Node/tsc/Vitest/doctor/demo 命令；中文模式也漏掉等义的平台和不可变运行描述。所有六份报告用同一事实清单复核，同时纠正自动误放行的事实矛盾。
3. 隐藏惰性检查误查 `runtime.sqlite`，真实 Store 文件名是 `kodo.sqlite`。复核遍查所有既有 oracle fixture 中两种文件名、数据库附属文件和 `owner.lock`，不重新生成产物。
4. 功能任务未将内部文件白名单展示给模型，且漏掉公共 API 新类型导出。多份交付除要求文件外，仅在 `src/application/index.ts` 导出新增 `PackageVersion` 类型。复核只接受相关、已声明的类型导出，不接受其他运行时改动，保留原有导出；另补完整交付副本的静态验证。

完整逐项改分、依据和确认错误见证据目录 `report-audit.json` 与 `audited-results.json`。原始表与复核表同时保留，不能拿原始误判计算完成率，也不能隐藏事后修改规则。

### 副本边界与一次超时

工具动作复核发现两个污染轮次：

- `onboarding-pi-1` 多次在父仓库读取源码、测试和文档，执行验证，之后才回到任务副本并比较两个源码树。报告内容按清单得 100 分，但不满足任务原先明确要求的“仅使用当前项目副本、不读取父目录源码”，不计为有效成功。
- `pagination-pi-2` 先读取父仓库未注入故障的正确实现，随后读取父仓库 `scripts/comparison/real-tasks.mjs`，包括隐藏 oracle；后来将副本修正。独立功能、测试和静态检查通过，但这不能代表盲测解题能力。该轮还在 900.677 秒期限被终止，没有最终答复，按内容清单为 90 分，严格失败。

两轮的时间、token 和费用全部保留，未删除、替换或选择性重跑。`artifactSummary` 单列只看产物的结果；总览的严格完成率再执行任务本来就有的来源边界约束。边界复核发生在事后，原 v1 自动程序只检查交付文件范围，没有检查读取来源，这是评测实现的限制。

日志表明超时的 Pi 在多数时间检查了错误的父仓库，回到正确副本后又开始全量测试，尚未结束就达到期限。记录能支持“目录选择与过量验证消耗了时间”，不能将这 15 分钟全部解释为 Pi 内核处理速度。

所有轮次统一检查结构化工具输入、绝对路径和相对逃逸候选，再核对候选输出；详情 `boundary-audit.json`、`boundary-actions.json`。声明过的祖先依赖、自建临时 fixture、目录/git 元数据探查不视为解题源码。Pi 第二轮上手任务读取父级 `.gitignore`，Pi 第二轮版本任务有一次父目录列表，两者单列披露；未由这些动作读到解题源码或评测内容。此审计不能证明进程级隔离：可信宿主进程仍能访问副本外，未来严格盲测应将评测程序和参考源码置于进程不可访问的环境。

## 消费核算

费用遵循用户指定的此前口径（2026-10-20 历史费率）：非缓存输入 ¥0.50/百万 token、缓存输入 ¥0.01/百万、输出 ¥2.00/百万。

```text
估算人民币 = ((输入 - 缓存输入) × 0.50 + 缓存输入 × 0.01 + 输出 × 2.00) / 1,000,000
```

缺少缓存字段的已知输入按全部命中/全部未命中给下限/上限。非 429 响应缺少 usage 则记未知，不能当作 0；429 沿用此前约定按零 token 记录。HTTP 200 流在 finish_reason 与 usage 返回后由客户端关闭可记为 `CLIENT_ABORTED`，这不自动等于请求失败，需检查原流完整性。

**token 是实测，人民币是历史费率估算，实际账户扣费不可确认。** 当前公开 pricing 未列出该精确模型 alias；账户 token 为 unlimited，usage 接口 `total_used=0` 不能证明没有扣费。原生 CLI 的 `cost=0` 是自定义模型未配置价格，也不作为账单。实际模型身份能核验到供应商请求/响应的 `deepseek-v4.1-flash` 字段，不能独立证明供应商背后的权重。

# 操作系统沙箱

CLI 显式使用 `--sandbox`，库使用 `new Application(dataDir, provider, onText, {sandbox: {network: 'none'}})`。未启用时保留原有可信进程执行方式。能力包的自定义工具和本地 MCP 始终使用原生沙箱，没有普通进程回退。

```powershell
node 'dist/cli/index.js' doctor --sandbox
node 'dist/cli/index.js' run '检查项目' --sandbox --allow-exec
node 'dist/cli/index.js' run '修改并验证项目' --sandbox --allow-exec --allow-write
```

网络默认关闭，`--allow-network` 必须和 `--sandbox` 一起使用。`exec` 授予启动程序的权限，沙箱内修改工作区还需要独立的 `write` 权限。`process.run` 即使被宿主声明为可信只读命令，也以只读工作区运行。CLI 验收命令采用同一沙箱政策。

运行内 shell/process 命令、结构化宿主任务检查及原生 `verify.run` 共用 `KODO_RUN_OUTPUT_DIR`，默认 `COVERAGE_FILE` 为其中的 `.coverage`。显式宿主环境或命令内覆盖继续生效。目录按私有存储位置和运行 ID 隔离，位于系统临时目录；只向当前运行的沙箱授予该精确目录，不扩大工作区写范围，也不暴露私有存储。只读 shell 仅获只读输出视图；写类 shell、进程工具和原生宿主验证可写运行输出，不能据此修改范围外的源码。Windows 的只读视图使用调用专用快照，输出环境路径随快照映射，显式覆盖到其他位置的覆盖率路径不变。输出跨命令和同一运行重启保留，不参与源码版本检查；不同续接运行有各自目录。运行结束不自动删除，直到宿主清理临时目录；需要长期保存的证据仍应转为 artifact。每次调用的其他临时目录和 HOME 仍会在调用结束后删除。

固定输出已在 Windows AppContainer 和 WSL Ubuntu 的真实 bubblewrap 后端验证：跨命令读取、不同运行输出隔离、只读工作区保持只读，以及原生宿主验证复用覆盖率输出。

工作区的 `scope.read/write` 在原生后端落实；缺省范围表示整个工作区，空列表表示不授予对应访问。写入根在操作系统层通常也需要读及元数据权限。允许启动的程序可以读取其运行所需的系统资源；这不等于宿主文件系统完全不可见。工作区外的程序文件可执行，工作区内程序必须在获准读取范围且不在受保护目录中。

Linux 启动时略过尚不存在的精确文件或目录挂载，不再让未来文件阻断无关的读取、环境查询或测试。不会创建空桩或扩大父目录权限：若只授权某个尚不存在的文件，先用原生 `write` 创建，下一次 shell 启动会挂载该文件；只有父目录本来就获准写入时，shell 才能直接在其中新建文件。新增目录也需要先由原生文件工具创建，或位于已有的可写目录内。

启动前会检查现有 `.git`、`.kodo`、`.env*`、常见凭据目录、密钥文件、硬链接和特殊文件；Windows 同时排除重解析点。Application 额外屏蔽实际私有数据目录。保护扫描不跟随链接，不承诺抵御另一个有宿主用户权限的进程在扫描后修改文件或权限；请勿把宿主并发写入的新秘密放进已授予的工作区。

`createSandbox({workspace, scope?, write?, network?, readOnlyPaths?, deny?})` 提供独立执行接口。`run(program,args,{stdin?,env?,cwd?,signal?})` 接受参数数组，输入最多 1 MiB，总输出最多 2 MiB，默认期限 120 秒。仅继承启动所需的最小环境，其他环境变量必须由宿主显式传入。`readOnlyPaths` 是宿主指定的代码及依赖资源，不接受模型动态扩大授权；它允许在被屏蔽的登记目录内仅暴露明确选定的资源树。

| 平台 | 实现与依赖 | 执行限制 |
| --- | --- | --- |
| Windows | 受限 AppContainer（LPAC）、`registryRead` 能力、Job Object；系统自带 .NET Framework C# 编译器 | 只读 shell 使用只读输出视图，可并存且不占持久写入互斥；同一 Windows 用户同时仅允许一个修改工作区或持久运行输出目录的沙箱，冲突明确拒绝。网络允许政策仍受 Windows AppContainer 回环地址和监听限制影响。 |
| Linux | bubblewrap、用户／挂载／PID 等命名空间；断网时附加 seccomp，禁止创建可寻址 socket、connect 与 io_uring，允许匿名 AF_UNIX socketpair 供进程内事件循环通信 | 必须安装 `bwrap` 且内核允许所需命名空间；未知架构或预检失败拒绝执行；系统运行目录只读。32 位旧式 socketcall 仍拒绝，仅支持直接 socketpair 系统调用。 |
| macOS | 系统 `sandbox-exec`、默认拒绝的 Seatbelt 文件及网络规则 | 禁止创建子进程，防止脱离进程组的后代在结果返回后继续修改文件；需要派生进程的程序会失败。 |

Windows 为每次执行分配独立身份；目录使用继承 ACE 避免大型依赖树逐文件启动开销，受保护路径使用显式拒绝覆盖继承授权。修改现有工作区文件前记录完整性标签，退出后恢复；新文件去掉临时身份并恢复普通标签。若宿主目录只授予当前所有者 `Modify` 而没有设置完整性标签所需的 `WRITE_OWNER`，launcher 仅在标签操作期间临时授予该权限位，随后按原始二进制描述符恢复 DACL。写入沙箱使用跨进程互斥与恢复日志，前一次异常终止的日志必须先清理才能开始下一次写入。Job Object 在退出、强制结束或清理时终止后代。清理失败保留日志位置并明确上报，启动后的写操作记录为未知，继续执行前须核实。

Windows 不修改管理员拥有的 Node/npm 安装目录权限。程序及显式只读资源复制到调用专用目录；直接指向资源树的路径参数会映射到快照，包内相对导入继续可用。资源内部不能含链接或特殊文件；代码不应硬编码开发机绝对安装路径。可写工作区保持原位置。由于需要临时完整性标签，长驻的可写 MCP 服务会占用唯一写入沙箱，其他写入应先关闭该服务或使用只读 MCP。

本地 MCP 的沙箱范围在连接时固定。运行只能使用不超出自身权限和文件范围的服务；较窄的子任务无法借用较广范围的长驻进程。沙箱 MCP 请求取消或超时会终止连接并等待清理，不自动重启和重放写操作。远端 MCP 的副作用发生在远端，仍由绑定的服务负责权限控制。

本机已实际验证 Windows 读写范围、受保护／工作区外资源拒绝、断网、子进程继承、强杀清理、并发只读恢复、本地 MCP，以及能力包工具与 npm 锁定依赖安装。Linux 子任务并行另在 WSL Ubuntu 验证，范围见下文；macOS 本轮未实际验证，跳过结果不视为原生验证通过。

## 子任务并行

2026-10-31 已在本机 WSL Ubuntu 的真实 bubblewrap 后端验证：两个独立子检出的 shell 可以并行，主目录原生读取不被它们阻塞；结构化宿主检查可以并行；一个子命令超时并完成效果和解时，兄弟命令仍能正常结束并继续写入。这是 Linux 执行路径的验证，不代表 macOS 或 Windows 写入沙箱已经支持同样的并行。

普通 CLI 需要明确开启 `--sandbox`，或在 Application 配置中传入 `sandbox`。默认可信宿主执行方式不自动变更，未隔离 shell 继续锁主目录与所有子检出。

Frontier runner 的新 `--kodo-tool-profile lean-team` 实验默认启用网络关闭的沙箱；`--kodo-no-sandbox` 用于显式复现旧的无沙箱条件，其他配置可用 `--kodo-sandbox` 开启。两组选项互斥，实际布尔值写入 manifest 和 trial.json。旧冻结 trial 未记录该字段时仍按未启用处理。做委派/单人对照时两组应选择相同隔离配置。

启动器在启动模型进程和本地 relay 之前执行 `doctor --sandbox --json`，将结果写入 state/sandbox-preflight.json；后端不可用或探针未成功则停止，不能回退到普通进程。Dockerfile.trial 为新构建安装 bubblewrap；已存在的镜像不会被自动修改，必须重建并记录新镜像摘要。容器内核还必须支持所需 namespace；仅安装命令不代表隔离已可用，也不会自动扩大容器权限。

2026-11-02 再次在 WSL Ubuntu 验证了独立子检出进程重叠时主代理读写继续、同一子检出内读取等待写入、宿主检查并行及超时后兄弟任务继续。分析脚本另输出 lockWait 的累计等待和时间并集，避免把模型并发误当成工具并发，或把多个等待者重复计入墙钟。

宿主工作区锁现在取运行实际检出路径，但仍在共同 session 协调域中参与冲突检查。快照在主锁内固定提交和持久引用，随后释放主锁，异步创建子检出。捕获记录用于中断后恢复相同版本；检出准备失败、开始和结束都有事件及耗时记录。调度器在准备期间允许主代理继续工作，锁重试有宿主侧间隔。

集成先非阻塞预留主工作区，再取得子检出锁进行检查和提交。主锁忙时只排队，不反复记录相同的宿主提交；子锁忙时释放主锁后再重试，避免把锁等待变成 `NO_PROGRESS`。权限、任务代次和主运行终态仍在取得锁后复查。

任务声明的文件范围继续生效。测试需要的依赖应在可读范围或受支持系统运行目录内；产生缓存的路径必须获得对应写入授权或使用任务私有临时空间。没有将任意测试命令自动当作只读，也没有放宽交付范围。

快照支持项目内、目标存在且不属于受保护路径的相对符号链接，按 Git `120000` 模式保存链接文本，不将目标内容复制成普通文件。未修改的链接可随快照保留，子任务仍只交付普通文件变更。悬空链接、循环链接、工作区外或受保护目标会明确报错；Windows 无创建链接权限时检出失败，不静默转换成文本文件。

修复后的 statemachine 项目在宿主和 `network=none` 沙箱中均通过 1,404 项原有测试（另有 143 跳过、44 项预期失败）。这覆盖 Python asyncio 和 pytest-xdist 的实际运行；其他项目的依赖与本地服务仍需独立预检。

# 协作收益对照：真实仓库协议加固

本实验保留 P0/P1，不继续叠加提示。先判断指定合理分工在一个真实仓库任务上是否有收益，再评价自主选择是否利用机会。创建数量不作为质量或自主成功的替代指标。

后续针对本批暴露的收尾问题，已单独完成[交付闭环修复与验证](delivery-closure.md)。本报告保留修复前原始条件和成绩，不与新试验合并。

**结果：尚无证据证明自主协作改善。** 正式六次运行中，指定分工两次均产生真实并行、采用子产物并通过代码验收，但其中一次最终回复为空；Solo 与自主组各一次通过代码及完整交付。三组完整交付均为1/2。自主组两次均无创建尝试；指定分工已观察到主代理上下文减少，但没有显示足以支持总体优势的耗时／费用收益，不能据此把零委派判为错误决策。

## 任务与实验条件

任务基于当前 Kodo 源码快照，包含两个独立的加固工作：Anthropic SSE 合法行分隔与截断处理；Responses 已结束输出条目与最终结果的一致性核验。分别修改两个提供者及各自新增测试，共同保留既有协议行为，由主代理执行集成构建、类型检查、lint 和六份测试（包括 provider-hardening 大输出回归）。这是新规格驱动的真实源码任务，不是线上缺陷回放，也未预先证明其协作收益。

三组各两次，顺序为 Solo、指定分工、自主选择、自主选择、指定分工、Solo。冻结运行时、卡片、工具、权限、初始源码、模型、预算、并发和验收条件相同；只改变用户任务中的执行方式指令。Solo 仍看得到协作工具，但按指令直接完成。指定分工分别负责两个模块，主代理核验子运行证据并完成集成验收。自主组不指定人数或要求创建。

模型 CodeGo / deepseek-v4.1-flash / Chat Completions。声明 1,000,000 token 合并窗口、393,216 最大输出；不设额外累计 token、请求数或任务时长上限。子代理上限8、模型并发2在各组一致。真实提示远小于最大窗口，不验收满窗口保真。进程工具属于可信高权限执行，不提供操作系统隔离。

验收在隔离副本执行；隐藏行为检查、参考实现及凭据不进入任务目录。先验证有缺陷版本被拒、参考修复通过，再发送真实请求。全部失败、重试和返工保留。模型结束后才执行隐藏验收，不将隐藏错误反馈给后续运行。

质量要求范围正确、独立行为验收通过、构建/类型/lint/新旧测试通过，同时主代理确实执行集成验证。比较全部尝试质量、端到端运行时间、主代理峰值输入、全会话 token 与费用；主代理上下文减少不能解释成总 token 减少。预声明10%的均值变化仅作实际收益信号，单任务每组两次不支持统计推广。指定分工通过不计自主成功。

最终文本审计：原自动布尔成绩漏查规格末尾要求的“最终说明修改和验证”。正式指定分工首轮代码与主代理验证通过，但上游以 stop 结束且正文为空。原始 result/summary 保留，不覆盖；audit 和 final-metrics 对全部同批产物统一补查最终回复并人工核对内容，不重跑模型、不反馈隐藏验收。后续评测入口补上空白终态检查及独立回归。非空只是必要条件，不宣称通用语义验收已经实现。

正式证据根目录：本机 `.kodo/collaboration-benefit-1792509373553`；运行前条件见 `conditions.json`，逐次实际请求、SSE、工具调用、SQLite 与验收输出保留在各组目录。费用采用人民币/百万 token：未缓存输入0.50、缓存输入0.01、输出2.00；429按用户规则计0，其他缺 usage 的请求保持未知，缺缓存只对已知消耗报告区间。

## 先导批次修正

先导目录 `.kodo/collaboration-benefit-1792507900550` 保留两次结束运行及一次被宿主主动中断的在途运行。初次预检漏掉 provider-hardening 的大输出兼容夹具：夹具允许完成条目省略 ID，而新规格原要求所有最终条目都带 ID。发现冲突后停止该批，不据此作协作收益或自主决策结论。Solo 未修改源码；指定分工的补丁过39项行为检查，但主代理遇到缺少合法 finish_reason 的上游流，未完成自身集成验证；中断的自主组不判为自主失败。

正式批次明确保留无 done 证据时省略最终 ID 的兼容性；显式提供的 ID 仍须非空且唯一，任何 done 证据必须有匹配的最终 ID。将大输出回归纳入必跑命令，并在发请求前验证：原版独立行为检查13/40通过，参考修复40/40通过；两者原有137项协议回归、构建、类型和lint均通过。先导计费单列，149次请求，已知小计¥0.61694403–0.62461302，另有1次未报usage；不冒充完整费用区间。

## 实际协作与执行问题

指定分工第一轮在58.85秒创建，第二轮在53.50秒创建；各有两名子代理，实际模型并发峰值均为2，不同运行请求重叠分别236.74秒、352.42秒。主代理分别通过 inspect_run 读取5次、12次原始子任务工具证据。按文件修改记录、调用归属及最终哈希复核，两个模块源码及各自新增测试由相应子代理完成并保留在最终目录，主代理完成集成检查。这证明协作发生且产物被采用，不能仅归结为形式创建。自主两轮均无创建尝试。

已确认的执行问题如下，均保留在原始请求、工具证据与最终工作目录中：

1. **交付收尾缺口。** 指定分工/1、自主/2、Solo/2均收到 stop 且最终正文为空，运行却为 completed；并非协作组独有。当前内核在未接入宿主完成验收器时允许保存空正文及 quality.not_checked（`src/runtime/coordinator.ts` 的完成处理）。内核已有可选验收器及纠正机制，但本实验不接入会反馈隐藏结果的验收器；结束、编译通过、测试通过、交付通过必须分开。不得把私有推理当成最终回复补出成绩。
2. **自主/2在反向测试后没有恢复。** 该轮先完成过可通过新增20项Anthropic测试的实现，随后主动破坏CRLF行为以验证测试能检出问题；目标测试如预期失败后，模型空白结束，未恢复源码、未新增Responses测试，也未清理4个临时脚本。最终隐藏行为37/40、范围／lint／回归不通过。因此不能简单诊断为“不会实现CRLF”，更直接的失败是破坏性验证没有闭环恢复和交付。
3. **Solo/2半成品结束。** 只改了两个源码文件，未新增测试、未自行执行验收，类型检查报缺少 CompletedEvidence、doneReasoning，退出码2；最终回复同样为空。短耗时属于提前结束，不是效率优势。
4. **验证协调与调用错误。** 指定分工/2在构建前跑含CLI的基线测试，出现3项缺dist失败；显式文件类型检查触发TypeScript6的TS5112提示。之后均修正。其他尝试还出现进程启动错误、补丁哈希冲突、证据分页位置或路径拒绝，并有修正记录。这些是具体执行开销，不能用工具状态 succeeded 覆盖实际进程非零退出码。
5. **额外验证有收益也有成本。** 主／子代理多次执行全局构建与类型检查，成功样本还做了扩展回归和反向测试，增加了协调与调用。不能把每一次重复验证或刻意制造的失败一概计为无效；必须结合是否定位问题、恢复并形成交付判断。

主代理的三份有效最终说明已与实际证据核对：Solo/1六份指定测试200项、全仓479项；自主/1分别173、452项；指定分工/2分别195、474项。这些是任务副本新增测试后的数量，不能与当前开发仓库416项回归混同。失败副本保持原样，未代模型修补后改判。

## 专用 Agent 的独立验收

这次实验只比较通用子代理的分工收益，不能验证能力生态。后续专用 Agent 场景应单独报告：

1. 主代理只获得候选卡片的用途、输入、输出及约束，检索并选择适当的已注册版本；保留不适用候选，避免把选择题退化成只有一个答案。
2. 专用 Agent 依靠自身独有的工具、技能或 MCP 完成任务，主代理不加载其内部方法。必须存在单靠通用提示无法等价完成的能力差异。
3. 输入有真实歧义时，专用 Agent 向持有资料的同伴或主代理提问，并依据回答完成；不预设每次必须提问。
4. 主代理读取交付物及合法原始证据后验收；错误卡片、缺资料、越权访问、错误交付物均有拒绝路径。
5. 独立评价卡片选择正确率、专用能力调用成功率、有用结果采用、问答闭环、上下文隔离、交付质量与总费用；不混入并行加速分数。

当前实现可解析/导入卡片、注册固定版本、按 ID/版本创建运行，已有消息与 inspect_run 证据入口。但卡片仅支持内置工具，description 校验后未保留到运行卡片对象；模型可用的协作工具没有卡片检索入口，Skills、能力包及 MCP 尚未实现。不能用继承通用卡片的子任务冒充这类生态验收。本轮不扩展这些接口，也不将未执行的场景计为通过。

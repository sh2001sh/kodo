# 子 Agent 探索成本核查与减法方案

> **说明：** 第 4 节减法清单继续有效；第 5、6 节的加法与执行顺序以 [最终产品定位与执行方案](kodo-final-positioning-20261103.md) 为准（上下文改为模型按需拉取，删除前先建黄金评测）。

日期：2026-11-03。状态：分析与提案；减法清单有效，加法部分已被取代。依据为五组复测原生数据库、[协作收益对照](collaboration-benefit.md) 与 [四方实验](experiments/kodo-fourway-isolated-20261101.md)。本次未修改代码。

## 1. 结论

**用户判断基本成立，但成本的来源不是“子 Agent 有特有知识”，而是交接：子 Agent 重新探索主 Agent 已知的内容，主 Agent 又重新读子 Agent 已读的内容。** 本批子 Agent 用的是通用卡或通用 implementer，几乎没有主 Agent 不具备的专属知识，因此交接成本没有换来任何能力增量。

## 2. 证据（statemachine 五组，每组一次）

统计脚本：`.kodo/scratch/reread/reread.mjs`。读取范围包括 `file.read` 与 shell 中的 `cat/sed/head/grep` 等只读命令；不含 pytest。

### 2.1 子 Agent 重读主 Agent 派发前已读的文件

| 组 | 各子 Agent：重读数 / 子 Agent 读取文件数 |
|---|---|
| 常驻 | 2/3、5/14、3/19 |
| 普通 Skill | 4/16（explorer）、6/13、6/9 |
| 阶段标记 | 7/9、9/13 |
| 检查点 | 6/13、2/11 |
| 动态工具 | 10/15、4/17 |
| **合计** | **64/152（42%）** |

### 2.2 主 Agent 在子 Agent 结束后又读同一批文件

常驻 25/36，普通 Skill 19/38，阶段标记 2/22，检查点 14/24，动态工具 3/32，**合计 63/152（41%）**。

其中一部分是集成核验的必要复读，不能全部算浪费；但它说明子 Agent 返回的摘要不足以让主 Agent 直接使用。

### 2.3 时间与费用

| 组 | 子 Agent 输入占比 | 主 Agent 等待子 Agent | 墙钟 |
|---|---:|---:|---:|
| 常驻 | 44% | 22.6 分钟 | 54.3 分钟 |
| 普通 Skill | 26% | 0（explorer 串行占用 5.7 分钟） | 34.4 分钟 |
| 阶段标记 | 8% | 0 | 29.9 分钟 |
| 检查点 | 19% | 5.5 分钟 | 74.7 分钟 |
| 动态工具 | 42% | 9.9 分钟 | 20.8 分钟 |

普通 Skill 组的 explorer 读了 16 个文件，与主 Agent 的读取 100% 重合，并在任务开头串行运行 342 秒；它是“专门探索”最典型的成本样本。

### 2.4 既有对照

- [协作收益对照](collaboration-benefit.md)：指定分工与 Solo 相比，耗时只快约 4%，费用高约 71%；主 Agent 峰值输入低 27.6%，但全会话 token 更多。
- [四方实验](experiments/kodo-fourway-isolated-20261101.md)：Kodo 未委派，耗时第二短、费用第二低，验收全部通过。
- 负责人模式与方法实验：自主委派 0/7；通用方法自主加载 0/8。

### 2.5 边界

每组一次、单一编码任务，不能估计总体效应。`file.patch` 要求本运行先 `file.read`，部分重读是工具合同强制的，不全是模型行为。大量相互独立的文件并行阅读（如几十篇文献）仍可能是子运行的有效场景，本批数据没有覆盖。

## 3. 推论：把“子 Agent 拥有知识”改为“上下文编译器拥有知识”

交接成本来自两个缺口：子运行拿到的是手写任务包而不是已知事实；结果以摘要返回而不是可寻址的证据。上下文编译方案正好对着这两个缺口：

- 子运行从同一持久存储编译上下文包，继承已读文件的证据与哈希，未变化的文件不再重读；`file.patch` 的前置读取规则应接受“本会话已读且哈希未变”的证据。
- 子运行结果写回存储，主 Agent 按指针取回原文，不再靠复读核实摘要。
- 方法（团队规则、领域知识）作为编译器可加载的内容，不再需要一个独立 Agent 承载。

## 5. 加法清单（按新定位）

技术创新（上下文编译）：

1. 编译器改为任务入口与压缩检查点触发，执行中只追加；重建前比较重建成本与后续节省。
2. 被移出内容保留指针，可在目标变化时重新编入；每条内容带来源哈希与新鲜度。
3. 子运行（fresh/fork）的上下文包由编译器生成；结果写回存储。
4. 上下文清单：每次任务展示用到的文件、决定、历史及来源。
5. 验证：深埋事实 QA、目标切换取回、128k 模型完成长任务，对照 off 与 summary。目标是接近开卷质量、接近闭卷成本。

体验优化（独立推进）：

6. 手机端：局域网配对 PWA，发任务、通知、回答、审批、看结果；远程中继后置。
7. 业务文件读写：PDF、docx、xlsx、pptx。
8. 默认身份改为通用工作助手（`src/runtime/lean-prompt.ts:13`）。
9. 修复五组复测暴露的写范围冲突与 502 重试窗口（删除任务图后需在保留的 spawn 路径上复核）。

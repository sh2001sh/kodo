# 检查输出保留与证据复用

本轮实现针对重复获取测试输出和重复验证，不新增交付门槛，不自动跳过检查，不启动付费实验。

## 证据与归因

- 历史 #117→#118：同源码版本、同检查参数，改变查看器后重跑，约 39 秒。保留早期输出可避免为补看覆盖率明细而重跑。
- 历史 #157→#162：同源码版本，中间只有读取与提交，约 40 秒。这里有两个独立问题：查看器应不影响检查身份；但 #157 的 `; git diff` 掩盖了检查退出码，不能因身份相同就认定通过。
- 当前源码已支持 awk 查看器。修正重点是引号与重定向识别、提交后的证据复用，以及旧输出的读取入口；不再将所有问题归为缺少 awk 白名单。

## 已实现的行为

### 输出

lean-solo / lean-team 的可识别测试调用默认在 stdout/stderr 返回各自末尾至多 80 行，并沿用 12,000 / 4,000 字符上限；`preview: "tail"` 表明位置。原始捕获内容和实际退出码保存在已有 outputArtifact 中，可用 read 的 artifact 模式分页读取。前台和后台结束记录采用同样的输出方式，后台通知包含附件入口。

不另外创建一份日志文件，不把完整输出重复塞进模型上下文。非测试调用仍使用原有预览，旧工具视图不改变格式。

测试命令可以使用输出管道或文件重定向，工具按原命令执行，不因输出格式拒绝或改写命令。可识别的过滤会标记 `outputFiltered:true`：附件保存的是 shell 实际返回的流，不包含被命令过滤掉的内容或只重定向到文件的内容。`capturedComplete` 仅表示捕获流没有因上限被截断，不代表测试输出未经筛选。直接运行测试仍是保留完整输出的推荐方式。stdout/stderr 之间的 `2>&1` / `1>&2` 合并不丢内容。

保留现有进程捕获上限 **2 MiB**。超限会停止捕获/进程，并标记 outputLimitExceeded、capturedComplete:false；不能将其当作完整输出或通过证据。未实施原草案中的 100 MB 新上限。

### 检查身份与证据

- 沿用规范化 key：工作目录、测试运行器、参数及环境赋值；去掉 timeout 和输出查看器。完整参数序列已经可比较，不另存重复的参数哈希。
- 引号内的重定向字符属于参数，不被误删；支持 `pytest>log` 这种无空格写法。输入重定向、命令替换、复杂脚本等不能可靠解析的调用不产生通过证据。这里只做已识别语法的提示，不承担 shell 权限分类。
- 历史 awk/grep/tail/git 查看器可参与识别，但身份匹配与退出码可信度分别判断。被分号、`||` 掩盖的结果仍为未知，除非已有严格规则能验证保存的退出码。
- 同版本、同检查先前确实通过时，重复提示附上原成功时间和输出附件入口。当前调用依然执行。
- 无法解析的复合命令仍记录 `check.started`，但版本为 `null`，不扫描工作区，不把“先修改、后检查”的结果归到调用前版本。可信的首次全套通过提示要求检查开始和结束的工作区版本一致；版本未知或改变时只保留实际命令结果，不宣称最终版本已通过。
- 成功的原生 Git commit 不再单独阻断提示；仍须核对工作区内容版本。修改内容、失败/结果未知的 Git 操作、原生写入或集成仍阻断对应证据复用。环境变化或不稳定测试可以合理重跑。

### 执行指导

主代理和实现类子代理的简短提示增加以下指导，不增加自动检查调度：

1. 用小型可重复用例定位级联问题，集中获取独立失败；不指定框架专属参数。
2. 集中修补覆盖率缺口，再统一检查。
3. 默认格式化修改和新增的路径；项目或任务要求更大范围时遵循其要求。不使用不适用于所有格式化器的通用 `--files` 模板。
4. 根据需求验证行为组合和边界，不能只看分支覆盖率。

子代理继续专项验证，主代理负责集成后的项目要求；只读角色不接收编辑或测试指导。主提示及工具定义仍受原有体积上限约束。组合用例由任务决定，没有添加固定的全项目测试骨架生成器。

委派在接口和责任明确后进行，紧密耦合的工作保留在同一执行者。交接区分已实现行为和接口计划，提供入口与已确认环境，不要求重走项目探索。依赖主代理尚未实现的行为时使用既有 self/after 节点。主代理提前识别验证要求，合并最终全套与所需覆盖率；没有强制委派数量、复验次数或新增调度层。

Git 的模型视图直接复用内核参数 schema，包括条件必填项。过期文件错误给出当前视图可调用的 read 参数，并说明 shell 读取不会刷新原生编辑的观察版本；原有一致性检查继续生效。

## 验证与限制

确定性测试覆盖历史命令匹配、掩盖退出码、引号与重定向、参数差异、提交后同版本/变更版本、未知复合命令版本、检查期间内容改变、失败和结果未知的提交。真实 Bash 测试覆盖通过与失败的 npm test、原样执行管道/重定向及其捕获边界、普通查看器、Unicode 尾部截断、附件分页和后台落盘；Git 模型参数与执行参数同步验证必填条件。

这些测试证明记录与提示机制成立，不证明模型一定少跑测试，也不证明总体速度或费用改善。本轮不运行付费实验。

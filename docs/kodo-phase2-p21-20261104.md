# 阶段 2 增量 P2.1 归档检索：实施与门槛结果（2026-11-04）

依据 [阶段 2 设计](kodo-phase2-design-20261104.md) §3 P2.1 与 §2 验收口径。分支 `phase2/archive-search`，门槛通过后合入 `main`。

## 1. 实施内容（`489b320`）

| 位置 | 改动 |
|---|---|
| `src/storage/history-index.ts`（新增） | 历史全文索引：`history_records` 按摘要去重存文本，`history_text` 为 FTS5 trigram 表，`history_postings` 记录每条文本出现在哪个归档消息或工具结果，`history_sources` 标记已建索引的来源。首次检索时建表，不检索的存储没有这些表 |
| `src/runtime/history.ts` | `searchHistory` 改为一次查询：先把授权运行的全部归档（含当前上下文快照）与工具结果增量写入索引（来源不可变，每个只建一次），再用 `LIKE` 查询（三个字符以上走 trigram 索引，更短的中文词在同一表上扫描）。空白分隔的多个词须同时出现在同一条记录里（ASCII 不区分大小写）。命中返回片段与精确的 `history.read`/`inspect_run` 指针；`next` 只翻更多命中，不再有逐页扫描预算。之前的检索/读取结果不入索引，避免回显 |
| `src/runtime/role-view.ts` | 默认视图开放 `history.search`（与压缩摘要里的指引一致） |
| `src/tools/index.ts` | 工具说明改为“一次覆盖本任务全部保留历史”，去掉 `maxScanChars`，`limit` 上限 5 → 10 |
| 测试 | 默认工具清单与字节数（11,829 → 12,572）、默认请求快照、视图测试更新；新增一次检索覆盖大归档、中文两字词、重复记录去重与翻页的用例 |

对照验收口径：质量 100% ≥ 开卷的 90%；未命中缓存 23.4k ≤ 闭卷 2 倍（约 38.7k）；单次输入总量最大 279k ≤ 30 万上限。**三项通过**。总量上限余量不大：每次答题约 8 次调用、每次带约 3 万基础上下文，问题更多时最先触到的是这条线。

P2.2（指针清单）的触发条件是“不知道能查而放弃”的格子，本次归档条件没有出现，暂不做。

**黄金评测里没有一格调用过 `history.search`**（窗口 1M，这些任务不触发压缩），候选与对照的唯一差别是请求里多出的 743 字节工具定义。差异集中在跨批次已知的两种失败模式（日期陷阱、引号转述），扩样后两边持平，Fisher 精确检验不显著（data-03 p≈0.4）。

**结论：P2.1 通过**（合格数差异不可检出，记录在案；成本与违规项通过）。

## 4. 其他观测

- 主运行重读率 25.9% → 13.5%，子运行重读主运行已读文件 61.4% → 77.8%：两项都与本增量无直接关系（没有调用检索），是 P2.3/P2.4 的目标指标，作为同时段参照记录。

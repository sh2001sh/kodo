# 内核真实任务能力评估（2026-10-20）

当前内核搭配本机 Qwen3.5-9B，可以完成明确定位、上下文较小的单文件修复；尚不能在本次配置下可靠完成跨文件调查、报告交付和双子代理开发任务。主评估 **0/6 通过**，另行开展的定向修复 **2/2 通过**、定向报告 **0/2 通过**。这些样本不足以推断其他模型或配置的成功率。

本次没有修改内核来改善成绩。工作目录中 `src` 的 13 个文件与测试前副本逐一比较 SHA-256，全部相同。预置缺陷仅存在于任务副本中，不是发现原仓库已有这两个缺陷。

## 测试条件与验收方式

- Windows，Node.js 24.13.0；真实 `ChatCompletionsProvider` 连接本机 llama.cpp，使用 `Qwen3.5-9B.Q6_K.gguf`，没有启动 27B。
- 服务地址 `http://127.0.0.1:18091/v1`，模型别名 `kodo-local-qwen35-9b`；服务上下文 8192 token，temperature 0，启动参数含 `--reasoning off`。
- 每次使用独立会话和真实项目副本。主评估每类任务重复两次；运行中没有人工提示、代写文件、替换模型回复或干预工具结果。
- 每个会话预算：500000 token、70 次工具调用、240 秒活动时间；单模型输出最多 3072 token，内核上下文上限 20000 字符。普通任务最多 26 次模型调用，协作任务最多 40 次；最多两个子代理，模型请求串行。
- 20000 字符是本次针对 8192 token 服务选择的实验限制，不是内核默认值，也不等价于 tokenizer 的 20000 token。结论针对这一明确组合。
- 代码任务必须真实修改代码、成功执行相关测试、通过独立行为验收，并遵守修改范围。不能以模型自述或运行状态代替验收。
- 独立验收程序放在候选工作区之外，重新编译候选代码后检查行为。先验证原始代码通过、预置缺陷代码失败，再开始模型任务。它不调用模型。

分页验收检查中文、emoji、引号和反斜杠内容能逐字还原、游标严格前进、非法参数被拒绝、其他会话不能读取归档。卡片验收检查 LF/CRLF 身份相同、其他内容变化仍改变身份、不支持的 schema 被拒绝。组合验收遇到首个错误即停止，失败输出不代表其后检查已经执行。

报告任务要求保存可读产物、根据真实文件说明能力与限制、引用来源、提供至少三条有效命令。自动内容检查只作为必要条件；成功报告还需要人工检查事实。本次没有成功保存的报告产物。

## 已确认的问题与仍不确定的部分

**1. 大工具结果与上下文压缩形成重复探索。**

首轮报告的第 2 步读取 `docs/design.md` 后，事件 seq 29 记录上下文从 46770 字符缩至 7977 字符，省略 10 条消息。检查第 3 步真实模型请求，已经没有此前的文件读取结果，只剩初始约束与归档提示；模型随即再次列目录和读 README。报告两轮各压缩 6 次，最终耗尽调用数。分页两轮分别压缩 9、6 次；协作首轮包含子运行共 16 次。

对应代码为 `src/runtime/context.ts:113`：按完整轮次尝试保留近期历史，最新一轮装不下时直接停止保留。`file.read` 当前只支持整文件读取、上限 64 KB，不能按行或片段读取；文件虽符合工具大小限制，也可能超过这次模型上下文的可用空间。原文归档仍可用，但本次模型没有主动调用 `history.read`。

已经确认的是实际信息丢失和重复轨迹；“改成某种摘要一定能解决”尚未验证。优先修复方向应是有界文件读取、对大结果给出可继续读取的引用、保留足够任务进展，再复跑原样本。

**2. 长报告的工具调用格式失败，内核错误分类不足以定位。**

定向报告没有发生上下文压缩，却均得到 `MODEL_TRANSPORT`；内核对同一请求重试三次后失败。测试结束后单独重放第一轮失败请求，只捕获协议、不执行工具，确认 HTTP 初始状态为 200，但 SSE 内出现服务端错误码 500，提示 `Failed to parse input`，且没有 `[DONE]` 或正常结束原因。

错误中的 `artifact_write` 工具文本缺少完整的 JSON 闭合，独立 JSON 解析也返回 `Unexpected end when deserializing object`。服务日志另外出现 grammar 重复次数超出限制的警告；它是否导致本次格式错误尚不能确定。需要同时检查本地模型服务的工具模板／约束生成和内核的协议错误诊断，不能简单归因为网络断线，也不能只把失败算在模型规划上。

**3. MODEL_INCOMPLETE 的原始结束原因未留存。**

三次主任务得到这一错误，内核拒绝执行不完整响应中的动作，行为符合当前保护规则。但保存的错误只有通用分类，没有原始 `finish_reason`，不能确认每次都是输出长度耗尽。对分页第一轮的失败请求单独重放时，返回正常 `tool_calls`；没有重现原错误，也没有执行其中工具。这两次协议重放不计入任何任务通过率。

**4. 多代理调度存在，成功完成协作尚未证明。**

首轮的创建、等待、共享预算保留均有真实记录，但没有任何子任务完成修复。下一步应先解决单代理的信息保持，再重测主代理拆分、子代理修改、主代理独立验收的完整链路；本次无法给出协作成功率保证。

# Kodo 往返压缩与交付证据优化方案（2026-11-01，修订 2）

依据：`docs/experiments/kodo-fourway-isolated-20261101.md` 与 `.kodo/fourway-isolated-20261101/` 原始 relay 计时、Kodo 可见工具索引。本方案只针对已测到的问题，不包含已测得的收益。

## 问题与证据

| 问题 | 证据（Kodo 单格） | 影响 |
|---|---|---|
| 请求轮次多，每轮动作小 | 188 次请求，首字等待合计 1,345 s，流式生成仅 357 s；167 次请求只调用 1 个工具；每请求工具参数 569 字符，其他三方约 1,000 | 减少无新增信息的往返；7–9 s 是本轮估计，不是固定收益 |
| 读后才能改 | 15 次纯读取请求的下一请求即编辑同一文件，合计 147 s；3 次 FILE_UNREAD | 候选重复读取；需区分理解上下文与仅满足工具前置条件 |
| 同文件分次编辑 | 9 次编辑请求紧跟同一文件的上一次编辑，合计 81 s | 候选合批机会；依赖测试或读取反馈的连续编辑属于必要迭代 |
| 任务外搜索 | #19–#23：diff `develop`、全盘 grep/find、curl 上游 API、翻缓存 | 需区分必要资料查询与获取其他实验答案 |
| 交付证据不完整 | #179 mypy `EXIT=1` 后 #183/#185 改引擎，未再跑 mypy；覆盖率 99% 后最后全套未带覆盖率；最终答复均未说明 | 四方共性，属机制缺失 |
| 退出码被掩盖 | #101/#115/#118/#124/#129 以 `; echo EXIT:$code` 结尾，外层返回 0 | 证据判定失真 |
| harness 间隙 | 请求间隙中位数 0.52 s，Pi/DSH 约 0.08 s，累计约 80 s | 次要，先定位 |

零委派本身不列为问题：前两轮委派实验分别用了 46.7 和 61.8 分钟，但配置和时段不同，不能据此单独归因。委派收益另用可拆分任务验证。

## 修订原则

仅删除重复且没有新增信息的处理，不给复杂任务的探索、修改、请求数和检查次数设门槛。允许读取依赖源码、查文档和比较 Git 分支；评测中获取其他运行答案的问题由实验隔离与来源约束处理。

## P0 证据披露复用现有答复流程

- 不新增 check-ledger、完成拦截、纠正次数或额外模型请求。交付证据要求放入现有 lean 提示：报告最终版本上的实际结果，以及失败、未达标、未验证的任务要求（包括覆盖率目标）。
- 不自行增加四类必需检查。检查范围来自任务和项目要求；专项通过不等于全套通过，子检出通过不等于集成后通过，命令退出 0 不等于覆盖率达标。
- bash 描述提醒在过滤或记录输出时保留检查退出码。工具仍返回原始结果，不自动执行或跳过命令。
- 现有同命令、同版本提示保留其事实表述，不将其升级成自动跳过。代码或环境变化、缺少证据、排查不稳定测试时允许重跑。
- 这是提示改进，不是宿主强制验证：最终答复是否准确披露，需要通过真实日志核验，不能宣称有了提示就一定做到。

## P1 精确编辑复用已有内容

- lean-solo 主运行与 lean-team 的 edit 在本运行从未原生读取过文件时，允许直接执行唯一精确替换。可复用 shell 输出、用户提供的片段和交接内容，不再机械要求额外 read。
- 模型仍应获得足够上下文；唯一匹配只证明定位明确，不证明理解了调用关系和行为边界。
- 每项替换按顺序在前一项替换后的内容上唯一匹配，所有项成功后才写入。歧义或缺失匹配不落盘。
- 已读或写过的文件发生变化仍返回 FILE_STALE；准备写入期间变化仍拒绝；write 覆盖已有文件仍须先读。旧工具视图、写权限、锁和恢复流程保持原有语义。
- 成功后 recordWritten，后续编辑使用已观察版本。同步更新 read、edit 描述和 lean 系统提示，删除互相矛盾的先读要求。
- 已有会话保留保存的系统上下文；新会话采用新提示。lean 编辑执行语义随当前构建更新，已有会话的旧提示可能仍引导一次重复读取，不改写其历史。

## P2 允许合批，保留反馈驱动的分步工作

- 鼓励把独立读取、搜索和已经确定的修改合批。
- 删除“同一文件所有修改必须一次完成”和连续编辑提醒计划。需要中间读取或测试反馈时分步处理。
- 收尾复用仍然适用的验证结果，完成后交付，避免可选打磨；时间提醒不再要求“只跑一次关键检查”。
- 不增加搜索限制、工具数量调整、并发上限调整或新配置。

## 测量与实验

请求数、首个模型内容等待、读后编辑、连续编辑、检查耗时只作为观察指标，不作为交付门槛。首次字节/心跳与首次模型内容分开；工具重叠时间按区间并集计算。候选重复操作需检查是否带来新信息，不把正常迭代计作浪费。

实现后运行编辑成功与失败路径测试、旧视图回归、类型检查、ESLint 和全量产品测试。需要证明速度与质量时，使用冻结构建和独立容器，旧、新构建各至少两次同期交错运行，报告全部结果及失败原因；本次实现不自动启动付费实验。

复杂任务需另选跨模块任务与需要测试反馈的任务。委派收益另用可拆分任务验证，委派与不委派各两次；不以出现委派为目标。

## 验证口径

- 编辑行为：未读且唯一匹配可执行；任一匹配失败不产生部分写入；已观察版本过期仍拒绝；整文件覆盖仍要求先读；旧视图保持既有行为。
- 结果质量：独立验收和旧行为不能以减少轮次为代价。历史 statemachine 的 72/72、1,286/1,286 是该任务的比较基线，不是所有任务的固定要求。
- 交付准确性：实际通过、失败、未达标和未验证项与最终答复一致。
- 效率：同质量下是否减少重复读取、重复检查和无效往返。删除“请求数 ≤160”“读后编辑 ≤5”的硬验收，不用机械次数评价复杂任务。

## 2. 评测与门槛工具（阶段 1 中形成的做法）

1. **同时段对照**：模型服务的输出会随时间漂移（同一份 1b 代码，早上 report-01 6/6、晚上 2/3），从 1d 起每批对照同时段的上一批代码，不再只和早上的基线比。
2. **成本/耗时按样例中位数判定**：候选每格 ÷ 对照同样例的中位数，取中位数 ≤ 1.10；均值只作参考（单格失控会把均值抬高 25% 以上）。
3. **复测与扩样**：`compare.mjs --recheck` 合并同代码复测；陷阱型样例（data-03）用扩样判断。
4. **子运行样例 sub-01**：9 个文本样例从不派生子运行，sub-01 用 `run-shape` 守住“主 Agent 确实派出子运行”。六组数据里主 Agent 每次都派出 5–6 个子运行。
5. **默认请求护栏**：`tests/default-request-invariants.test.ts` 对主运行与子运行首请求做逐字节快照，并检查系统提示身份。
6. 工具：`run.mjs --rescore --rerun-commands`（修检查脚本后不必付费重跑）、`run-shape` 检查类型、`subrun` 类别。

# Ky totalTimeout v2-r10 真实模型对照结果

日期：2026-10-27。注册：`ky-total-timeout-v2-r10`。输出：`.kodo/ky-total-timeout-paid-20261027-r10`。

## 总体结论

**当前证据支持“摘要压缩能可靠执行，并在本任务中降低工作上下文峰值和累计 token”，但不足以支持默认开启或稳定提速。**

- 已完成 5 个 trial；4 个完整交付。摘要开启的 D1、C1、C2 均为 14/14，摘要关闭的 A1 为 12/14、B1 为 14/14。
- 三个摘要 trial 共启动并安装 14 次摘要，失败 0 次；摘要调用占这三次运行原始 token 的 4.09%。
- 单次安装前后，估算上下文平均从 45,994 token 降到 31,385 token，平均缩减 31.7%，范围 26.4%–38.0%。
- 只有 3/14 次安装达到 28,672 token 的软目标。其余摘要仍有净缩减并成功继续任务，但预期头部空间没有完全释放。
- 开放委派的 D1、B1 均创建 0 个子代理；用户停止时的 B2 也创建 0 个。完成样本的自主委派采用率为 0/2，计入中断样本仍为 0/3。
- 矩阵按用户要求在 B2 中途停止。A2、D2 未运行，B2 不作为完成样本；因此结果是探索性、非平衡对照，不能做稳定优势或统计显著性声明。

价格未配置，本文只报告 token，不把 token 换算成金额。`加权 token` 是 relay 按缓存读取 10% 计量的成本代理，不等于实际账单。

这证明当前版本已经越过此前的“摘要输出截断/无法安装”问题：所有真实摘要请求都产生了可安装结果，没有失败或重试丢失。

但 `installed` 不等于达到目标预算。11/14 次安装后仍高于 28,672 的安装软目标，最高为 34,083。实现明确允许“有净缩减但未达到软目标”的摘要安装，因此这不是契约失败；它说明压缩能够腾出空间，但释放量经常小于预期。

### 配对比较

| 配对 | 调用变化 | 原始 token | 加权 token | 主输入峰值 | Agent 时间 | 质量 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| C1 对 A1 | +9.1% | -13.2% | -7.1% | -19.0% | +8.4% | 14/14 对 12/14 |
| D1 对 B1 | -49.7% | -57.7% | -53.9% | -16.8% | -49.4% | 均 14/14 |

两个直接配对都显示主输入峰值下降约 17%–19%，原始与加权 token 均下降。这是压缩的最明确资源信号。

端到端时间并不一致：C1 比 A1 慢 8.4%，D1 比 B1 快 49.4%。B1 是明显长尾，发生了 199 次模型调用、180 次重复读取和 13 次公开测试调用；D1 没有实际委派，因此不能把差异归因于子代理并行。当前只能判断摘要可能减少长上下文下的重复行动，不能判断它稳定提速。

C1 与 C2 的调用量（96/99）、原始 token（2.93M/2.97M）和主输入峰值（44.5k/44.6k）接近，说明摘要资源形态在两次无委派重复中较稳定；Agent 时间仍从 14.6 分变化到 18.6 分，模型和工具路径波动明显。

## 委派效果

本批没有发生自主委派：D1、B1 和中断前的 B2 均未创建子代理，主代理也没有可采纳的子结果。

因此本实验只验证了“委派工具可用但模型没有采用”，没有验证委派能否提升质量、成本或时间。B1 的高调用量也不能解释为委派开销，因为其全部 199 次请求都属于主代理。

## 中断与排除

- B2 按用户要求在 step 63 中断：64 次模型调用，其中 63 次已结算、1 次响应未知；至少 2,363,709 原始 token、约 9.45 分钟，子代理 0。它不是失败交付，也不进入组均值。
- D2、A2 未开始。
- 正式矩阵完整度为 5/8，且缺少第二个无摘要 Solo 基线 A2；不能形成平衡的两次重复结论。
- v2-r9 曾完成一个 A1，但该批因人工误读旧预算建议而中断，且夹具版本不同，不并入 v2-r10。

## 结论边界与建议

1. **压缩机制本身已可用。** 14/14 真实摘要安装、0 失败，三次摘要 trial 全部正确交付，说明此前预算和安装链路的主要故障已修复。
2. **容量保护效果成立。** 两个直接配对的主输入峰值都下降约 17%–19%，摘要安装平均缩减 31.7%。
3. **成本收益有正信号但未证实稳定。** 两个配对 token 都下降；时间一快一慢，且 B1 长尾显著影响聚合结果。
4. **软目标达成率需要继续观察。** 仅 21.4% 安装达到 28,672 token；应继续记录 `targetMet`，不要把“安装成功”直接解释为“预算目标达成”。
5. **自主委派没有被采用。** 当前频率为 0%，没有任何委派收益证据。
6. **覆盖率和闭卷准确率不在本任务验收范围。** 14 次摘要成功安装只证明消息被处理并产生净缩减；T01–T14 证明最终工程实现正确，不证明摘要逐事实保留率或闭卷问答准确率。

基于当前不完整单任务证据，摘要压缩应继续作为条件性容量保护能力，默认开关不宜仅凭本批改为开启。若以后恢复实验，优先补同一冻结版本的 A2 与 D2，或在第二个不同工程任务上复核；不需要先扩展摘要或委派功能。

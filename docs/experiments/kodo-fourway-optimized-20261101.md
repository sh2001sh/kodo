## 中止原因与已得结果

Pi 第 9 次请求开始读取自身工作区外目录，第 11 次读取历史实现及测试，第 16 次应用历史补丁，之后又读取同批 Kodo 源码、会话记录并复制测试。这是共享宿主环境造成的交叉污染，不能作为独立完成任务的成绩。发现后停止批处理与模型进程，保留最后原始状态和 `administrative-stop.json`；未完成的原始 `result.json` 仍为 running，不代表进程仍在运行。

Kodo 单独结果：2,013.491 秒、176 次模型请求、15.36 credit，新要求 72/72、旧行为 1286/1286，reward=1。没有委派，原生模型并发峰值 1，不能由此证明并行、宿主重验或 Git 交付入口带来收益。137 次协议完成后的连接取消不计为模型失败，176 次均 HTTP 200 且协议完成。

Kodo 首次修改在请求 43、启动后 383.499 秒；原生模型耗时 1,729.230 秒（85.88%）。28 次 pytest 中有 8 次广域检查、208.114 秒，只有一对相同版本的普通全套与覆盖率全套，可合并但后者提供新增证据。最后必要检查之后又有约 44.523 秒模型往返。完整逐请求审查见本批 `analysis/kodo-full-review.md`。

公共任务未要求创建 Git 提交，未提交不是本轮缺项；最终声称宿主无 Git 仓库不准确，实际只是沙箱隐藏 `.git`，且从未尝试已提供的宿主 Git 入口。最终自报的 Ruff/Mypy 两项问题经隔离基线对比确认原已存在；Mypy 只覆盖生产包。

截至中止，Pi 已知费用 6.04 credit，最后一次请求用量缺失；旧批次总费用至少 21.40 credit。污染格的费用单列，不从实验成本中删除。详细证据见 `analysis/contamination-summary.md`。

## 修复

- `task recheck`：已完成子代理的宿主检查失败时，可更正检查命令并直接重验，保留检出和 generation，不再启动子模型；依赖失效、未决副作用和活动工作仍阻止重验。通过后才提交、集成。
- pytest 缓存默认写入每运行输出目录；显式 pytest 选项仍可覆盖。独立不可写工作区验证中，原配置因缓存警告失败，新配置正常通过。
- lean 命令的短输出也保存为 artifact；后台完成事件保留完整捕获结果，重启后仍能读取。重定向到临时文件的内容仍须使用 `KODO_RUN_OUTPUT_DIR` 留存，不能从 stdout artifact 还原未输出的文件内容。
- 主代理通过既有 `job` 工具的结构化 Git 操作，在原工作区创建请求的分支、提交显式文件；保持无关暂存和工作区修改。子代理不开放该入口。Git 开始后结果不明的错误保持未知写入屏障，不能仅凭源文件未变化自动和解。
- lean 状态帧只重复显示 unknown/running/planned 调用，已结束的失败保留在工具结果和审计历史中。
- 提示强调旧行为兼容、专项检查、原仓库交付及检查通过后停止无关打磨；不要求所有任务必须委派。
- Linux 只读运行环境包含系统命令链接和字体配置，使已安装的 awk、Graphviz 能正常使用。
- 指标改用原生模型事件计算 Kodo 并发；relay 连接占用单列。后台测试采用完成事件计时，排除锁等待，pytest 帮助/版本查询不计为测试，明确的包装退出码单独保留。

主代理工具数维持 9，定义序列化为 8,970 字节；系统提示 1,599 字符。lean-solo 保持 6 个工具，子代理没有 Git 交付能力。

## 解释限制

一次固定顺序运行不能排除网关时段和模型随机性的影响，也不能单独证明某项修复的加速效果。历史 Kodo 三格带额外委派指令，环境工具也不同，不能作为本轮严格对照。

WSL worker 没有统一 8 GiB 内存上限。Kodo 使用禁网工具沙箱，竞品沿用其默认隔离且可访问宿主网络；这一条件差异必须随结果披露。原生事件缺失时并行、耗时和费用字段保留未知，不能填零。

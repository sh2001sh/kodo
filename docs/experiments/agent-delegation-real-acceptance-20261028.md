# 委派优化真实任务验收：2026-10-28

结论：创建、续接、身份和上下文保留机制已经可用；本批没有观察到真实模型自主采用这些能力。默认策略的 7 轮真实任务中，`spawn_agent`、`explore`、`followup_task` 均为 0。显式工具链正控制成功创建 1 位队友，执行 2 个子 run，其中 1 个由续接产生。不能据此宣称已经提升自主委派率、并行效率或会话成本。

使用本机已配置的 `codego1 / deepseek-v4.1-flash`，Windows、Node 24.13.0。所有模型任务在隔离副本中执行，运行时来自本轮成功构建后冻结的 dist；任务源码也冻结。新增功能、文档修订和分页修复产物均留在实验副本，未合入生产源码。

调查对照只切换因子 B：基线 `{A:true,B:false,C:true}`，新指导 `{A:true,B:true,C:true}`。生命周期实现、工具、模型、窗口和预算相同。两组各两次，按旧／新／新／旧顺序执行；每次新指导调查后增加同主题追问。关闭全局用户指令和委派提醒，不启用动态组装，保留默认条件性摘要。已核对实际模型请求：新指导、explorer 名册、创建、续接及待办工具确实可见。

自主任务说明没有要求创建队友、复用队友或并行处理，也没有预先创建团队。正控制另行明确要求使用工具，不计入自主采用统计。功能任务末段与正控制存在时间重叠，因此功能任务墙钟仅作单次观察；调查 A/B 样本均串行执行。

小任务直接完成符合设计。调查和跨 API／CLI 的实现任务也没有产生队友，本批无法证明新指导提高了采用率。两次追问之前均没有现存队友，因此它们不构成“已有合适队友时是否自主复用”的有效检验，不能把续接次数为 0 当成续接工具失败。

显式正控制完成了“创建 → 等待 → 检查原始读取证据 → 主任务追问 → 同一队友续接 → 检查结果”。8 项控制条件全部通过：

- 只存在 1 个稳定 `agentId`，有 2 个不同的子 `runId`，两轮都完成。
- 实际成功调用 `followup_task` 1 次，续接运行的 `continuationOf` 指向前一轮。
- 第一轮队友读取的随机标识保留在第二轮工作上下文中，并在两轮交付中完整返回。
- 随机标识文件仅由第一轮队友成功读取一次；主代理未读取，续接未重读。
- 主代理使用带 `call_id` 的 `inspect_run` 消费了真实工具证据。

该组耗时合计约 156.6 秒，24 次模型调用、323,816 token。两次绝对路径参数错误与一次报告字段错误均被拒绝后纠正；这些重试计入完整会话用量。

实测交付中有两项需要关注的模型行为：

1. 第一次生命周期追问把 `interrupted` 说成释放容量的终态，还使用了不存在的 run 状态名 `succeeded`。`src/runtime/types.ts:170` 的 `terminal()` 实际只包含 `completed / failed / cancelled`；中断任务仍计入活跃容量。第二次追问正确说明了该定义。这是模型答复的事实错误。
2. 功能任务对 `src/application/index.ts` 连续四次填写同一个错误 `expectedHash`：第 47 个字符填了 `a`，实际为 `c`。模型最终把拒绝写入归因于 CRLF，并声称哈希相同；记录中的参数与错误返回直接反驳了这个解释。另一次文档补丁也填写了错误哈希。工具的冲突检查按预期拒绝了这些请求，没有观察到模型所称的 CRLF 工具故障。

111 项委派回归覆盖活跃名额释放、显式累计限制、8 个完成后可创建第 9 个身份、批量容量拒绝、忙碌队友、幂等重试、上下文与最终回答延续、旧待办刷新、重启恢复和主任务后续轮次管理等。它们使用确定性模型，不能代替真实自主采用结果。

评测中修正了三项环境或计分问题，保留全部首次记录，没有重新抽样挑结果：

- 初始答案解析器把单独一行的 `0.3` 误当成“第 0 题”，将新指导样本 1 错记为 7/8。离线修正题号边界后为 8/8，原始回答及原评分均保留。
- 分页副本运行测试生成了 `node_modules/.vite` 和 `.vitest-cache`，最初被误算成额外源码修改。排除标准测试缓存后，实际只修改 `src/runtime/history.ts`，独立相关测试通过。注入错误后的原有测试循环没有页数上界，负样本触发了测试进程内存耗尽；没有再次运行这个负样本。
- 功能评估器只做了 TypeScript 编译，漏建 Windows `node-pipes.node`，首次 67 项回归中 1 项因此失败。随后在独立验收副本运行项目原生构建脚本，保持模型源码产物不变，再跑相关回归及资源测试，6 文件 74 项全部通过；11 项行为验收、类型和静态检查也通过。最终结论采用这次完整构建后的复验，首次失败没有覆盖。

全批共 208 次有用量记录的模型调用、5,310,632 token，未知用量调用为 0，包含基线、默认任务、主／子运行、续接与摘要。未查询实际账单，不报告货币成本。没有执行全仓测试，也没有验证其他模型、macOS/Linux 或真实 8 队友压力下的性能。

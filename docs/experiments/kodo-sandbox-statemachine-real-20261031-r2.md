5 项失败属于两类：

- `test_changes_cleared_between_macrosteps`（同步、异步）：状态进入时把默认值初始化也加入 `DataChangeInfo`，无显式数据修改的下一宏步仍返回一条初始化记录。期望空列表，实际长度为 1。该类问题在历史实验中也出现过。

## 修复范围

- `src/sandbox/posix.ts`：断网环境支持 Python asyncio 所需的匿名 AF_UNIX socketpair，保持地址型 socket/connect 的原有限制。
- `src/runtime/execution-snapshot.ts`：快照保留工作区内有效相对符号链接，以 Git `120000` 模式保存链接文本。采集期间再次核对链接类型和目标；无效目标明确报错。
- `src/runtime/execution-checkout.ts`：检出显式启用 `core.symlinks=true`，不将符号链接静默转换为普通文件。
- `scripts/comparison/frontier/relay.mjs`：增加可选绑定地址，本轮 relay 绑定 WSL 回环地址。默认行为不变。
- Linux 集成测试夹具同步文件实际可执行权限与 Git 模式，避免只改索引后被重新暂存覆盖。

## 实验设计与限制

任务是 Frontier Harness Eval 的 `python-statemachine-state-data-scoping`，基线为 `8d17ba9f6ba8420cf05fddb94013bc221ed9a222`。沿用上一轮的明确委派要求；这是一次定向委派实验，不能证明模型会自发委派。只跑 Kodo 一格，没有同期基线、Pi 或其它 harness。

配置：`lean-team`、因素 ABCDE、任务协议 3、`deepseek-v4.1-flash`，模型并发 3，活动子任务上限 8，1,048,576 上下文、393,216 输出上限、5,400 秒总预算、120 秒工具默认超时。运行使用冻结的 Linux 构建，模型运行期间没有人工修改任务代码或注入指导。

运行环境为 WSL Ubuntu，CPU 亲和性限制为两个核；没有总体 8 GiB cgroup 内存上限。Python 为 3.12.3，上一轮 Docker 为 3.12.12；依赖文件从原镜像复制。独立验收继续使用原 Docker verifier（两个 CPU、8 GiB、断网）。因此历史数值只作描述性参照，不能计算修复带来的因果加速或成本优势。

`uv`、`ruff`、`mypy` 等工具并未全部提供；预检证明原项目测试可以运行，不代表项目所有开发命令均可用。全套测试中的 Graphviz 相关跳过项保留原样。

## 已观察到的剩余问题

1. 委派前探索偏长。主代理先建立公共实现，再启动 SCXML 和图示两个子任务；两个子任务均成功创建隔离快照，并通过宿主验收后集成。
2. 新文件范围的沙箱适配不足。子任务范围包含未创建的测试文件时，部分 shell 命令在启动前被拒绝；错误未指出具体缺失文件，子代理反复探测环境。新文件通过原生写入创建后，测试可运行。
3. 沙箱临时文件只活到一次命令结束。覆盖率日志写入 `/tmp/cov-output.txt` 后，下一条命令读不到；模型后来改用输出 artifact 读取。
4. 构建缓存路径需要明确约定。子代理的 `compileall` 试图写入只读目录的 `__pycache__`，随后改用临时缓存路径。不能把这类失败算为代码语法错误。
5. shell 读取不建立原生编辑的版本记录。主代理修改 `async_.py` 和 `docs/states.md` 时各出现一次 `FILE_UNREAD`，重新用原生读取后成功。
6. 收尾仍有重复检查。子代理专项检查、宿主验收和主代理集成验证部分重叠；主代理全套测试后又跑了一次全套覆盖率检查。
7. 网关心跳可持续刷新字节空闲超时。第 234 请求耗时 400.853 秒，13.792 秒收到首字节，379.717 秒才有首个推理内容。应区分字节活跃与模型内容进展；落盘缓冲意味着不能只看响应文件大小推断首字节时间。

这些是本轮发现的后续优化项，不应计为已经修复。优化缺失路径与缓存时，应保留精确写入范围；环境事实需要随交接传给子代理。内容进展超时需要与长时间有效生成区分，不能把网络心跳当成任务进度。

优先顺序：先补模型内容进展的超时与失败恢复；再处理新文件范围、运行级临时目录和缓存目录、环境交接；然后统一最终验收，明确“需求行为核对完成后停止无关打磨”。本轮的 5 项功能失败也说明，需要把边界语义写进交接与验收，而不是用更高覆盖率代替需求正确性。现有证据不支持先提高并发数量。

## 记录口径

`relay/` 保存请求、原始响应与分段计时；`process/` 保存带时间戳的事件、工作区 diff、资源采样、原生记录和合成轨迹；最终补丁、状态数据库、编译产物、工作区归档及独立验收结果一并保留。

子检出归档是每 60 秒的采样，不能声称每个检出的最终目录均被捕获；集成交付以原生调用与内容寻址记录为准。资源采样来自共享 WSL 主机，不是容器专属资源计量。

relay 的 `cancelled` 可能是客户端在收到 `[DONE]` 后关闭连接，应结合 `protocol.status` 与原生模型调用状态判定。credit 全零不能证明免费，不能用于计算费用收益。锁等待时间按调用累计，不能直接当作可节省的墙钟时间。

复核入口：`analysis.json`、`audit/audit.json`、`audit/native-tool-calls.jsonl`、`trial/statemachine-kodo/verifier/reward.json`、`trial/statemachine-kodo/verifier.log`。`audit-live/` 是运行中只读采样的中间审计，最终数字以 `audit/` 为准。文件完整性清单位于 `evidence-sha256.json`。历史预检报告保持原文，仅追加本轮结果链接。

# 工程任务：区分单次请求超时与整体超时

当前 HTTP 客户端只有 `timeout`，难以分别控制每次尝试和包含重试的整次操作。请在提供的 Ky 工程副本中完成以下功能，交付实现、类型、文档和回归测试。

## 功能契约

1. `timeout` 表示每次请求尝试获取响应的时间上限，每次重试重新获得该额度；默认仍为 `10000` 毫秒，`false` 关闭单次尝试的超时限制。
2. 新增 `totalTimeout?: number | false`，单位毫秒。默认及 `false` 均表示不设置整体超时；有限数值表示本次 Ky 执行跨多次尝试共享的时间预算，不能随重试重置。
3. 整体预算涵盖请求尝试、重试间的退避/Retry-After 等等待，以及客户端为处理 HTTP 错误而进行的响应体读取和错误数据解析。相关挂起不能让操作无限超过整体预算。
4. 两个上限同时启用时，单次尝试不能超出剩余整体预算。整体预算耗尽时，以现有 `TimeoutError` 结束，不能因 retry limit 尚未用尽或 shouldRetry 返回 true 而继续发送请求。
5. `totalTimeout: 0` 应立即超时，不发送请求；`timeout` 或 `totalTimeout` 大于 `2147483647` 应按 `RangeError` 拒绝。其余已有参数语义保持兼容。
6. `retryOnTimeout` 保持控制单次尝试超时后是否重试；正常网络错误、HTTP 错误、重试次数和 hooks 规则不应因本功能退化。
7. 新选项支持普通调用、`ky.create()` 和 `extend()`；派生配置能覆盖或通过 `false` 关闭整体预算，并且不修改父实例配置。
8. 调用方主动取消仍遵守现有取消契约；取消或整体超时终止后，不得继续调度下一次请求。不要求强行中止无视取消信号的第三方代码，但不能继续安排自己的重试工作。

该功能不要求接管已成功交付的原始 `Response` 之后由用户自行消费的响应流，也不要求强制终止任意永不返回的用户 hook。它必须覆盖客户端内部的错误响应读取/解析路径。无需为未声明的输入类型额外设计新 API。

示例用法：

```ts
const result = await ky(url, {
  timeout: 5000,
  totalTimeout: 30000,
  retry: {limit: 3, retryOnTimeout: true},
}).json();
```

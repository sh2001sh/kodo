## 1. 真实需求，独立验收

给出工程缺陷报告或功能需求，让 Agent 自己决定调查、实现、分工和验证方法；在冻结代码与环境下，以产物行为独立验收。

不要求读取全部文档、固定文件顺序、创建一定数量子代理或达到一定上下文长度。如果无需压缩就完成，记为自然结果，不补填充文本让策略触发。

| 旧资产 | 后续用途 | 不再承担的结论 |
| --- | --- | --- |
| 分页微项目 A/B 与文档长度变体 | 摘要安装、回退、约束保留的机制回归 | 广泛工程收益 |
| 八个常量查询 | 工具可用性与轻量查询负控制 | 多代理应当优于直接执行 |
| 已使用的版本查询/onboarding | 开发集与评分器调试 | 未见任务上的确认性验收 |
| 手工生成的前端小应用 | 浏览器、截图和工具链检查 | 真实既有前端项目代表性 |

主任务必须有真实工程基底：源码、锁定依赖、可运行应用或库、原有测试和实际边界。合理的新需求标注为“真实项目上的新任务”，故障注入标注为“合成回归”，不能虚称来自真实用户事故。

## 2. 第一版任务集

E01/E03/E05/E06/E07 可从现有 Kodo 代码准备；E02/E04/E08 要选择独立真实仓库后冻结，当前未选定。源仓库未确定、参考解或验收未验证的任务不得进入付费矩阵。

确认性测试至少覆盖三个独立工程基底。五个 Kodo 任务不能冒充五个独立仓库；共享模块或协议的任务按任务族聚类。

| ID | 工程任务 | 预期规模 | 主要检验 |
| --- | --- | --- | --- |
| E01 | 历史记录分页重复/缺失回归 | 短 | 定位、正确修复、避免多余协调 |
| E02 | SDK 取消后仍继续重试 | 短至中 | 异步控制流、契约与资源释放 |
| E03 | 包版本查询 API + CLI | 中 | 跨层交付、兼容性、集成 |
| E04 | 列表筛选、排序、游标分页一致性 | 中至长 | 数据语义、多模块边界 |
| E05 | Web 面板断线恢复后的状态一致性 | 中至长 | 前后端联动、浏览器行为 |
| E06 | 运行取消与子进程收尾 | 中至长 | 生命周期、部分失败、交付 |
| E07 | 源码与运行证据联合故障定位及修复 | 长 | 多来源证据、可验证结论 |
| E08 | 多轮需求调整后的列表和导出功能 | 长、多轮 | 约束保留、需求取代、重新规划 |

规模是选题预期，不是 token 配额。难度须用参考实现和开发试跑校准；不能事后按某个 arm 是否成功筛题。

## 3. 逐项任务规格

### E01：历史分页回归

基底：Kodo 冻结副本。已有曝光的故障注入版本只进入开发集。

公开任务：

> 用户分页查看较长的历史工具输出时，下一页偶尔重复内容，某些带中文和 emoji 的记录无法完整还原。请复现并修复，保持现有 API 和跨会话访问边界，补充回归测试，交付根因、修改和实际验证结果。

独立验收：不同页大小、消息数、空消息、长输出下，分页组合等于原记录；游标严格推进并最终终止；Unicode 和转义文本无缺失重复；无效参数及其他会话引用继续拒绝；同一游标重复读取一致。使用冻结 seed 生成数据，不只验证公开示例。

游标语义在公开协议中明确。主代理直接修完可以是最佳结果，不能因未委派判失败。

### E02：SDK 取消与重试

基底：有真实 retry/AbortSignal 实现及测试的独立 TypeScript SDK，仓库、版本和许可证在制作阶段确认。

公开任务：

> 调用方取消请求后，SDK 有时仍会发出下一次重试。请修复传输中和退避等待中的取消行为，保持公开函数签名、正常重试规则与原有错误可识别性。补充测试并说明如何验证没有多发请求。

独立验收：开始前取消不访问服务；传输或退避期间取消后不再重试；暂时失败后成功仍正常；达到重试上限和非重试错误行为正确；连续调用不共享错误的信号状态；定时器、监听器及资源正确释放。

本地 HTTP 假服务记录请求顺序和次数，使用可控时钟/屏障，避免纯毫秒竞速。取消错误形态先从原 SDK 契约确认，必要时写进公开任务；不能用隐藏测试新增要求。错误修复“前台返回取消但后台继续重试”必须被拒绝。

### E03：包版本查询完整交付

基底：现有 Kodo 包管理。旧任务作为开发集；确认集须使用新需求或不同真实实现，不能只换版本数字。

公开任务：

> 为已安装包增加只读版本查询 API 和 `kodo package versions <author/name>` 命令，支持 JSON 与普通文本输出。版本按三段数字倒序排列，不存在的合法包返回空结果，非法 ID 失败。保留完整性检查，不启动包代码、不改变当前采用版本、不要求模型凭据。补充测试和使用文档。

独立验收：多包、多版本、两位数字混合排序；API 与实际构建后的 CLI 行为一致；JSON 字段与 stdout/stderr、退出码正确；目标包或 provenance 篡改时失败；包代码哨兵不执行；采用指针、不相关数据不变；不意外创建运行时数据库。

可以自然分工为 registry、CLI、验证/文档，但任务不强制分工。检查实际构建产物，不能只测试 mock 函数。

### E04：列表服务的数据一致性

基底：已有实际路由、数据层和数据库测试的服务项目，使用其既有数据库，当前待选定。不临时造一个单文件接口代替真实工程。

公开任务：

> 管理列表组合使用状态筛选、关键词搜索和翻页时会漏项或重复，页内排序也不稳定。请统一过滤、排序和游标规则，保持已有响应字段兼容。排序、相同键的次级顺序和并发新增时的语义以提供的 API 说明为准。补充集成测试和接口说明。

制作阶段公开固定：游标是否绑定查询条件、无效游标处理、唯一次级排序键、总数语义。验收不得替用户暗中作产品决定。

独立验收：固定数据库快照的全量遍历等于参考查询有序集合；相同时间戳、Unicode、空结果、边界页大小、无效游标与变更筛选符合契约；并发写入由确定性屏障调度，按已声明语义检查。通过实际 HTTP 路由和测试数据库，不强制参考解的内部 helper 或算法。

### E05：Web 面板断线恢复

基底：Kodo Web 协作视图及真实事件协议。先确认基线是否已有缺陷；如果已经正确，用可审计的最小故障注入形成开发回归并标注来源。

公开任务：

> 网络断开恢复后，任务列表偶尔重复，已完成的子任务可能重新显示为运行中；切换会话时可能混入旧会话事件。请复现并修复，使页面最终与服务端状态一致，保持既有交互与键盘可操作性，并补回归测试。

独立验收：真实浏览器回放断开、重连、协议允许的重放/重复事件，每个 run 只有一个条目且状态正确；切换后不接收旧会话事件；没有累积订阅和重复处理；错误提示、键盘访问、基础窄屏布局可用。只有协议允许时才测试乱序，不凭空增加上游不存在的情况。

以可访问名称或稳定公共测试标识检查用户行为，截图为辅助证据。服务在本机，事件序列冻结，不依赖公网。

### E06：取消、子进程与收尾

基底：Kodo 协调器、进程工具和恢复逻辑，固定平台。Windows 结果不能写成跨平台验证。

公开任务：

> 用户取消正在运行检查命令的任务后，后台进程有时仍继续运行，界面收尾状态也不一致。请修复取消传递、资源清理及状态记录，保留已有写入结果不确定时的恢复规则。交付测试与复现步骤。

独立验收：专用子进程在可控屏障处等待，取消后在合理上界内停止；只清理该 run 的进程，独立哨兵进程保持运行；取消期间不发起新工作；终态、用户可见结果和审计记录一致；未开始写、确认写完、写入结果未知分别按公开规则处理；重启后不自动重做不确定写入。

被取消的是测试应用内部 run，不是整场评测的 Agent 运行。Agent 仍需最终交付。所有测试进程和文件归属独立临时目录。

### E07：故障定位、补丁与运行说明

基底：Kodo 冻结副本与可重放的本地运行证据。制作确定性场景：中断恢复后同一待处理事件被重复投递，导致页面重复处理；如原代码没有缺陷，标明故障注入。

公开任务：

> 给定一次恢复后重复投递的运行记录、源码和本地重放方法，请定位触发条件与根因，修复问题，并提供简短 INCIDENT.md，包含证据、修改、验证和适用边界。区分直接观察与推断，不把未验证的平台行为写成结论。

独立验收：原始轨迹基线失败、补丁通过；改变事件 ID、批量和中断点的未公开输入仍正确；普通投递和会话隔离不退化；报告根因对应真实代码行为，复现命令可运行，验证声明与日志一致。错误归因和假称验证通过属于交付缺陷。

根因按事前事实/证据表复核，不能因路径和关键词出现就判正确。说明不按篇幅或引用数量加分。该题与 E05 有关联，应按关联任务族统计，不能同时充当两个独立项目。

### E08：多轮需求变更

基底：已有列表、筛选和导出基础的真实管理应用，独立于 Kodo，当前待选定。

三轮用户需求在运行前冻结，所有组在相同语义屏障收到相同消息：

1. 为事项列表增加筛选并导出当前结果 CSV；兼容已有 URL 参数，保留客户编号前导零，不引入新依赖。
2. 第一轮交付后澄清“当前结果”指全部筛选结果而不是当前页；增加截止时间排序；只替换列顺序要求，其余约束保留。
3. 第二轮交付后要求新建记录后列表和导出一致，并补最终使用说明。

独立验收：实际浏览器创建数据、筛选、翻页并下载；独立 CSV 解析器验证行集、列顺序、逗号/换行/引号转义和前导零；相同排序键按公开稳定顺序处理；旧 URL、兼容入口和锁定依赖不变；最终行为遵守有效旧约束与新要求，不沿用被取代的列顺序。

消息在阶段交付/终态屏障发送，不按某组的 token 数或摘要次数发送。阶段失败按预注册规则记完整任务失败，不跳过失败阶段只评成功后半段。阶段间保持连续会话和总体预算，不手动清空历史。

用户消息中仍可见的约束用于检查遵守要求，不能当作摘要记忆证据。若验证记忆，应另外选择早期业务观察中的事实，并核实其确已移出工作上下文。

## 4. 每个任务的最小资产

沿用现有 runner，不新建通用评测平台。每题制作：冻结源码与来源清单；公开任务和契约；已有开发测试/命令；工作区外的独立验收及 seed；参考解、至少两个错误修复、注册和结果格式。

公开测试是正常工程资产，应允许 Agent 使用和补测试。关键是最终验收不能只跑 Agent 自己写的测试，也不能公开所有答案后声称测到了记忆。隐藏验收只隐藏具体数据与实现，不隐藏需求。

评测器、参考补丁和其他组产物不进入被测工作区，shell/MCP/文件工具边界一致。只写“不看父目录”不构成隔离；平台无法落实时明确标注，不宣称已防泄漏。

Agent 停止后，在干净副本中用提交的源代码重新构建并运行外部验收，不信任被测输出中的 exit 0。依赖预先准备，避免联网安装波动。允许合理内部重构，不用验收强制参考解代码结构。

## 5. 先证明验收能区分对错

每题付费入场条件：

1. 坏基线在目标需求上失败，原有无关环境故障已排除。
2. 参考解通过需求验收、原有回归和边界检查，有真实命令输出。
3. 至少两个合理但错误的补丁被拒绝：只修示例、忽略校验、取消后仍后台重试、全局杀进程或只导出当前页等。
4. 同一产物连续三次离线验收一致；异步/浏览器任务使用可控事件、时钟和屏障。
5. 公开需求和验收项逐一映射，没有隐藏新增需求。
6. 评分程序和关键原有断言不能被删改绕过。合法新增测试/文档允许；行为变化确需修改既有测试时，公开允许范围，权威验收仍在外部。

坏基线、正确补丁、错误补丁都验证后，评分器才有资格评 Agent。

## 6. 统一交付评分

主指标是任务完整通过，另保留失败维度，不把所有断言混成一个容易掩盖严重错误的总分。

| 维度 | 依据 |
| --- | --- |
| 功能正确 | 公开需求对应的独立验收 |
| 边界与兼容 | 异常路径、原有 API 和回归 |
| 约束遵守 | 依赖、保护路径、会话隔离、进程归属 |
| 可用产物 | 应用/CLI 可构建运行，补丁、测试、文档齐全 |
| 交付真实 | 最终答复非空，与修改及实际验证记录一致 |

硬约束失败直接判未完整交付。说明性结论按预先事实表、盲于策略的复核检查；模型评审可以辅助，不能独自裁定关键错误。

每次记录：任务/代码/模型/策略/seed；各验收维度；所有输入缓存/未缓存/输出及未知用量；主任务、摘要、子代理请求分项；完整墙钟时间；主上下文峰值；恢复、委派、采用与集成复查开销。

费用含失败运行和所有维护调用。分别报告完成率、全批资源消耗及成功配对中的代价，不只挑各组成功样本。多道验收题、多个子代理不视为独立任务。

## 7. 协作与压缩分别如何使用任务

协作比较 Solo、可自主委派、相同配置加提醒；先两组定位，需要验证提醒时再加第三组。Solo 保留正常批量工具调用。整个 session 业务能力一致，避免协作组独享 MCP/Skill 而把能力差异误算成委派收益。卡片价值另设问题。

指定分工正控制从工程任务抽取子交付物，例如 E03 CLI 合同验证、E05 重连复现分析；不再以常量查找为主。正控制只验证执行能力，不证明自主选择正确。

压缩使用 E04–E08 等自然长任务，比较 off 与冻结 v3，允许相同的正常原文读回。未触发摘要的样本保留，并记录触发暴露情况，不能事后剔除。

分开注册常规条件与压力条件：常规工作预算测日常收益；压力条件对预先选定长任务统一减小工作预算，测容量压力下续做。不能靠无用资料填充达到阈值，也不能把压力结果包装为日常平均收益。

任务长度和预算在开发集校准后冻结。同一任务换 seed、窗口和重复次数不变成新的独立任务。

## 8. 首轮落地与成本控制

1. 先制作 E01/E03/E05/E06 的工程副本和独立验收，保留历史曝光标记；在验收可靠之前不跑模型。
2. 选定 E02/E04/E08 外部工程，补 E07 多来源任务。一部分任务留作策略冻结后的确认集，不参与调参。
3. 协作筛查：E01/E03/E05/E06 各跑 Solo 与自主组一次，共 8 次。只查明显质量和成本问题；没有委派是有效结果，不因此反复改同一题。
4. 压缩筛查：从已经准备好且开发校准有自然历史增长的任务中选 4 个，各跑 off/v3，共 8 次。委派策略固定，不把短题硬拉长。
5. 无契约缺陷和明显质量退化后，再按需要加入提醒、候选压缩或第二模型。扩大样本使用新任务/确认集，按任务族分析。

这些是探索规模，不代表统计验收。任务库无需立即全跑；预算逐轮冻结，停止、未知用量和证据保留继承整体方案 P0。

## 9. 本轮完成与剩余工作
